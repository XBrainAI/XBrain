# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

用户指令（2026-10-28 原话）："请分析 grade-insight/details 最新录入的考生纸质卷相关数据，联动早期录入的数据，这次录入的纸质卷是补充了具体的考题内容，所以需要对当前的考情分析评价体系进行重新设计，要求给考生提供更细更详尽的考情分析评估以及提升建议。请先设计，供我审核。设计包括考情分析模型、html可视化模型等。"

现状 = 首次观测（2026-10-28）：10 月首考的题级数据契约（gi-exam-data/1）已就位——全部 8 科有题级得分（题号/题型/分值/难度/得分），数学与生物另有逐题解析件（题干/选项/我的答案/参考答案/完整解析，analysisRef 覆盖 19/19 与 37/37）与知识点掌握度（51/21 条，含薄弱分类与重点标记）；站点端 GIAnalyze v1（R1–R7 规则 + 补救 top10 预估回收）与四 tab 详情弹层已运行。但研判引擎只消费分数元数据，题目内容、作答对照、解析文本完全未参与分析——只能回答"丢了多少分"，不能回答"为什么丢、丢在哪个知识节点、怎么补"。差距清单（G1–G7）与全部数据证据见方案稿 §1：grade-insight/方案-考情分析体系v2.md。

相似既有规格互链（背景，范围以本规格为准）：
- SPEC-004（站点融合阶段2——知识点透传，in-progress）：本规格承接其透传的 kps 并深化，不回退其字段与视图。
- SPEC-005（单考详情直观化，in-progress）：复用其弹层分页骨架、dataRef 懒加载与解析预渲染路径约定，不改其信息架构。
- SPEC-006（考系统分析报告，in-progress）：本规格扩展其引擎（GIAnalyze v1→v2）与仪表盘；R1–R7 与既有全部组件冻结不回退；其 §1.7 曾把"跨考联合分析"列为非目标——本规格在题级数据就位的新前提下解除该冻结（跨考层按数据到位自动激活设计）。
- SPEC-009（纸质卷转写markdown，in-progress）：题目内容层的生产管道，本规格扩展其提示词与转换器（v2），不改其既有交付。
- SPEC-010（数据文件身份信息脱敏，in-progress）：错因复核件与联合数据不新增身份信息，脱敏口径随其裁定执行。
- SPEC-007/008（XBrain全站UI重构，in-progress）：本规格只在 grade-insight 弹层既有信息架构内做内容级扩展，不改全站视觉体系。

## 1.2 目标用户与场景

家长/学生：单考后不仅能看到"各科丢了多少分"，还能看到"错题为什么错（错因构成）、哪些知识点最值得补（四象限）、未来 4 周按什么顺序补（复习计划+重练清单直达解析）"；第二场带题级数据的考试入库后，自动获得知识点掌握度演化趋势与顽固薄弱点预警。

## 1.3 业务价值与成功指标

价值：分析结论从"分数诊断"升级为"归因诊断 + 可执行行动"。指标：数学/生物错题 100% 有错因标注（人工复核后）；行动清单每条可执行（有重练题清单与解析链接）；跨考维度在第 2 考数据入库后零改造激活；R1–R7 既有结论零回退。

## 1.4 用户故事

- P0 作为家长，我想知道每道错题"为什么错"（概念/方法/计算/审题/步骤），以便辅导有的放矢。
- P0 作为家长，我想要一份未来 4 周的复习计划（按周、按知识点群组、带错题重练清单与解析链接），以便不必自己规划。
- P1 作为学生，我想在知识点视图看到"丢分多且没掌握"的高价值补强区，以便优先攻那里。
- P1 作为家长，我想跨考试追踪同一知识点的掌握度变化，以便发现"反复薄弱"的顽固点。
- P2 作为家长，我希望所有"预估/预判"都有口径标签（AI 预判+人工复核、规则估计），以便不过度解读。

## 1.6 体验意图

"为什么错→先补什么→本周做什么"三级问题首屏可答；所有预判带口径；解析一步直达（错题→题目全文→解析）。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

全栈四层设计（完整细节、字段示例与规则表见方案稿 grade-insight/方案-考情分析体系v2.md，本节为摘要）：

1. **数据层**：gi-exam-data/2 增量字段（questions[].cause/causeNote、kps[].kpKey/qNos，全 optional 向后兼容）；pipeline/kp-dictionary.json（gi-kp-dict/1，KP 全局稳定键，归一化规则固化）；pipeline/joint.js 生成 js/joint-data.js（window.GI_JOINT，gi-joint/1——选 JS 全局而非运行时 fetch：file:// 可用、无缓存坑〔SPEC-006 B5 先例〕、与 data.js 同模式）；acceptance v1.2 增 cause 覆盖与 qNos 一致性校验。
2. **错因模型**：CAUSE-TAXONOMY v1 固化 C1–C6（概念/方法/计算/审题/步骤/待标注）与可补性权重；AI 转写预判（transcribe-prompt v2，证据引用型输出）→ 人工复核件（md.错因复核-<科>.md）→ 回写 exam.json。
3. **分析引擎**：GIAnalyze v2 只增不改——L2 题级诊断（D1 九宫格/D2 错因构成/D3 KP 四象限）+ L3 跨考演化（E1 KP 演化/E2 顽固薄弱/E3 跨考错题本）+ L4 行动（A1 补救优先级=沿用口径×错因权重×顽固加权；A2 确定性 4 周复习计划生成器）；R1–R7 与既有仪表盘组件冻结。
4. **可视化**：V1 题级诊断散点（错题 tab）、V2 错因构成条（仪表盘分科卡）、V3 KP 四象限（知识点 tab）、V4 KP 演化折线（跨考激活）、V5 提升路径阶梯图（行动清单 v2）；移动端与术语纪律全量承接 SPEC-006 v5–v8/AC8。

分期：S1 数据与固化件 → S2 引擎与可视化（数学/生物全量，他科诚实降级）→ S3 跨考激活（条件触发，零改造）。

## 2.2 影响面

新增：pipeline/{CAUSE-TAXONOMY.md, joint.js, kp-dictionary.json}、js/joint-data.js、details/<考>/md.错因复核-<科>.md。修改：pipeline/{transcribe-prompt.md, convert.js, ANALYZE-RULES.md, DATA-CONTRACT.md, acceptance.yaml}、js/{analyze.js, app.js}、css/style.css、index.html、details/<考>/data/{exam.json 重生成, 系统分析.md v2}。→ 数据模型增量 + 引擎扩展 → L2。

## 2.3 数据与接口变更

- 契约：gi-exam-data/1 → /2（optional 增量，v1 件全兼容，不追溯改写历史件；10 月件按 v2 重生成）。
- 新 schema：gi-kp-dict/1、gi-joint/1（均登记 DATA-CONTRACT v2.0）。
- 站点接口：无对外接口变更；window.GI_JOINT 为页面内全局约定。

## 2.4 安全与合规自检

个人成绩延续既有裁定（站点密码门 + 数据不出库）；错因复核件不新增身份信息、脱敏口径随 SPEC-010 裁定；错因为推断输出——必须附解析依据句并标注"AI 预判+人工复核"，不冒充事实（AC6）。

## 2.5 回滚方案

删除 v2 增量文件/字段即可：GI_JOINT 缺失引擎自动降级单考模式；exam.json 可由 v1 管道重生成；固化件回退到 v1 版本号存档。规则升版须重跑历史考回归（SPEC-006 R8 纪律延续）。
