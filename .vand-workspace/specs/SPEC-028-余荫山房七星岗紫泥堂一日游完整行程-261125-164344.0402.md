# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

用户需求原话："按此编制四季景点新方案，注意去除`老人`相关的描述，输出通用版本。"其中"此"指 SPEC-027 候选稿中经多轮追问确定的走法——里仁洞本地肠粉早餐 → 余荫山房 → 紫泥堂（午餐＋散步）→ 返程；追问时用户又想起一处遗漏（原话）："我想起了，之前还曾经规划过回程去七星岗？请复核之前的规划历史，看来先要订正方案"。

规划历史复核（2026-11-25）：七星岗古海岸遗址科学公园在 SPEC-2026-0005（国庆收官日，2026-10-06）中排过三轮——第四轮作回程加项（15:25–16:05）、第五轮作首站、第六轮拆为独立的"Day 2 模块"（10-10）；该规格待确认的 4 件事后来以"都过去了，销掉吧"销项（TD-2026-0005，2026-10-24 cancelled）。**仓库内没有任何执行记录**，候选稿（SPEC-027）也未把它纳入比较——这是一处遗漏，需要订正。

要解决的问题：把七星岗补回这次行程，并在订正后的走法上出一份可直接照着走的完整逐小时行程；该行程是通用版，不写同行人员的特殊安排。

相似规格互链（背景证据，不承其范围）：SPEC-027（本次出行的候选稿规格，已交付；事实底稿与订正记录都在那里）、SPEC-2026-0005（七星岗的历史规划与实景图资料来源，in-progress）、SPEC-012（"候选对比 → 圈定 → 完整行程"同范式的交付体例先例）。本规格只做完整行程文稿，不重复候选比较，也不重写历史文稿。
