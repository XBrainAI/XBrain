# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

XBrain 是部署于 Netlify 的「统一门户首页 + 独立子站点」家庭知识聚合站，当前已积累：门户首页（`index.html`）、5 个内容频道站（健康 / 四季景点 / 学习与成长 / 生活点滴 / 采购与维护，合计约 40+ 页面）、2 个工具应用（grade-insight 成绩分析、query-system 中考志愿查询）与模板体系（`src/site-template*.html`、`brand/top-nav-template.html`）。

UI 依靠 README 规范（§四 Logo、§六视觉风格、§十 top-nav 模板）+ 模板复制 + 各页内联 CSS 自发演化，跨站一致性靠人工遵守约定维持；近期各站迭代节奏加快（grade-insight 仪表盘化、文章页 top-nav 化），规范偏离与样式重复有累积趋势。用户（km）拟对 XBrain 整体进行 UI 重构，**约束是不动 XBrain IP**（`brand/XBRAIN-LOGO-IP.md` 与 README §四/§六定义的 Logo 组件、`--xb-*` 色彩体系、Noto 字体、12/8/4px 圆角层级），需要一份覆盖全站的 UI 交互设计评估作为重构决策依据。

相似既有规格互链（背景证据，范围以本规格为准）：SPEC-2026-0002（grade-insight 三页直线信息架构重构——单站 IA 重构先例）、SPEC-005-单考详情直观化迭代-261023-105403.2676（详情页呈现与移动端适配先例）。本规格为全站级评估，不承其任何范围。

## 1.2 目标用户与场景

- **读者**：km 及家庭成员——手机为主的访问者，在各频道站浏览文章/记录，在 grade-insight 查成绩分析；
- **决策者**：km——阅读评估报告，在不损失品牌识别的前提下裁定全站 UI 重构方向与实施节奏。

## 1.3 业务价值与成功指标

现状 = 首次观测（2026-10-24 建立基线）：站点/页面数量、样式定义重复度、规范偏离项、交互模式清单。成功 = 报告产出**可裁定**的重构方案选项（≥2 条路径，含不动 IP 边界、成本量级、风险与回滚思路），且论断均有仓库内证据可复现。

## 1.4 用户故事

- **P0** 作为站点所有者，我希望获得全站 UI 交互设计的深度评估与重构路径选项，以便在不动 XBrain IP 的前提下裁定整体重构方案。

## 1.5 验收标准（可验证）

- **AC1**（Given 全部 HTML 站点 When 逐站分析 Then 报告覆盖门户首页、5 个内容频道站、grade-insight、query-system、模板体系五类对象，每类给出交互设计现状与问题清单）。验证方式：事实核证
- **AC2**（Given `brand/XBRAIN-LOGO-IP.md` + README §四/§六的品牌 IP 定义 When 给出重构建议 Then 报告明确划定"不动 IP"的保留边界清单，且所有建议不违背该边界）。验证方式：事实核证 + 专家评审
- **AC3**（Given 评估结论 When 呈报 Then 提供至少两条可选重构路径（含范围、成本量级、风险、回滚思路）与一条推荐项，供人工裁定；实施不属本规格）。验证方式：用户确认
- **AC4**（边界型：报告中关于跨站一致性、可访问性、移动端等的论断均附具体文件/行为证据，抽查可复现，无凭空断言）。验证方式：事实核证

## 1.6 体验意图

不适用：纯调研评估文稿，本规格不产生任何界面/交互变更。

## 1.7 非目标（本期明确不做）

- 不实施任何 UI 重构代码、不修改任何线上页面与品牌 IP 文件；
- 不引入构建框架/新依赖（选型属后续实施规格的决策点，本规格只提供选项）；
- 不重写既有子站内容与信息架构（grade-insight 的 IA 已由 SPEC-2026-0002 处理）；
- 不评估 query-system/other_infos 等内容工件本身的排版（只评承载它们的 UI 框架与导航交互）。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述（交付物 = 评估文稿，本章只写编制安排）

- **交付物路径**：`docs/ui/XBrain-UI重构评估报告.md`（项目自身目录，新建 `docs/ui/`）
- **章节骨架**：① 全站资产盘点（站点/页面/模板/体量）② 品牌 IP 边界界定（保留清单）③ 逐类对象评估（门户 / 频道站 / 文章页 / 工具应用 / 模板体系）④ 跨站一致性与样式重复度分析 ⑤ 问题清单（按严重度分级）⑥ 重构路径选项（≥2，含成本/风险/回滚）与推荐 ⑦ 分阶段实施建议
- **关键决策点（留人工裁定）**：纯静态共享 CSS/模板 vs 引入构建步；重构范围是否含 SPA 应用；灰度顺序
- **证据采集**：直接审读仓库 HTML/CSS/JS；体量与重复度用脚本统计（只读）；必要时本地静态打开抽验交互
- **编制方式**：主会话直接分析 + 并行探索子代理扇出，结论汇总落盘
