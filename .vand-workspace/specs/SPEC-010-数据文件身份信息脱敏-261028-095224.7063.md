# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

**现状（已核仓库实际）**：SPEC-009 T10 / DELG-001 完成 `md/` 目录身份信息脱敏并承接闭环后，独立复核发现身份信息明文仍在 `md/` **外的两处数据文件**：`grade-insight/details/高一/上学期/10月/data/exam.json:33`、`grade-insight/details/高一/上学期/10月/正式档案-高一上第一次月考.json:6`（证据：DELG-001 回执补充发现 1，请求方 2026-10-28 扫描复核属实，为全 details 目录 md 外仅两处）。该两文件是 grade-insight 站点的 **UI 数据源**（经 `data.js` / 前端渲染 / `netlify/functions/grade-store` 云同步链路消费），含学生姓名/班级等未成年人身份信息明文。

**不解决的后果**：私有仓库与站点数据中持续暴露未成年人身份信息；与 SPEC-009 已确立的"身份信息一律不录入/脱敏"口径不一致（`md/` 已脱敏、数据文件未脱敏，形成隐私边界漏洞）。

**相似规格互链（背景证据，不承其范围）**：SPEC-009（T10/AC8 确立 `md/` 脱敏先例与占位口径〈姓名〉〈班级〉〈考场号〉〈学号〉）、SPEC-001（月考成绩登记 data.js，数据契约先例）、SPEC-000（md/ 交付物）。本规格承接过程待办 TD-006，范围 = **数据文件（exam.json / 正式档案）身份信息脱敏**，不承 SPEC-009 的转写范围；因数据文件被站点/云同步消费，属数据契约面，与 `md/`（惰性文本资产）不同，故另立本规格。

## 1.2 目标用户与场景

家长/学生本人：希望 grade-insight 站点与其数据文件不再含身份信息明文；同时站点访问者不因脱敏失去既有成绩可视化功能。

## 1.3 业务价值与成功指标

消除数据文件中的未成年人身份信息明文暴露，使隐私边界覆盖到站点数据源。指标（首次观测 = 本轮）：① 脱敏后数据文件身份信息明文扫描 = 0；② grade-insight 页面正常渲染、回归测试通过（基线待本轮观测）。

## 1.4 用户故事

- P0 作为家长，我希望 `exam.json` / `正式档案` 中的姓名/班级/学号明文被替换为脱敏占位，以便仓库与站点不再暴露未成年人身份信息。
- P0 作为家长，我希望脱敏后 grade-insight 站点仍正常显示各科成绩与知识点分析，以便脱敏不破坏已建成功能。

## 1.5 验收标准（可验证）

- **AC1**（行为型）Given `exam.json` / `正式档案` 含身份信息明文 When 执行脱敏 Then 明文全部替换为统一占位（与 SPEC-009 口径一致：〈姓名〉〈班级〉〈学号〉等），扫描无残留。验证方式：自动化扫描 + 抽查人审。
- **AC2**（边界型）Given 占位值写入数据文件 When 站点经 `data.js` / 渲染链路读取 Then 页面正常渲染、无 JS 报错、成绩/知识点功能不回归。验证方式：回归测试（`node tests/run.js`）+ 用户演示。
- **AC3**（边界型）Given 身份信息字段被其他链路（`grade-store` 云同步、档案导入导出）消费 When 脱敏 Then 确认这些链路对占位值兼容、不因脱敏产生数据不一致或云端/本地分歧。验证方式：专家评审 + 代码核查。
- **AC4**（观测型·交付后复核）样本范围 = 脱敏后 grade-insight 全量数据文件与站点页面；判定口径 = 用户复核发现明文残留或渲染异常即反馈；闭环时点 = 反馈即修订并回写 5.2。验证方式：用户复核。

## 1.6 体验意图

站点显示的学生标识由明文变为脱敏占位（如档案名/标题处显示〈姓名〉），其余成绩可视化不变；不得因占位值导致空白、报错或布局破损。

## 1.7 非目标（本期明确不做）

- 不改数据 schema / 字段结构（只改身份信息字段的**值**）。
- **不回改 git 既往 commit 中的明文**（历史清除属人工另行决策，范式红线"不代改历史"）。
- 不动 `raw/` 原始素材与 `md/`（已由 SPEC-009 处理）。
- 不改成绩数值、题目、知识点数据本身。
- 不做站点功能改版或新增。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

**本规格为 L2**：Design 只到"影响面核查 + 方案"，**实施须待人工决策后开工，决策前不产出实现代码**（执行约定 2）。

技术路径：① 先做**只读影响面核查**——定位 `exam.json` / `正式档案` 中被哪些消费方读取身份信息字段（`js/data.js`、`js/store.js`、`netlify/functions/grade-store.mjs`、档案导入导出、页面标题/档案名渲染处），确认各消费方对占位值（含中文尖括号 `〈〉`）的兼容性；② 据核查结论决定脱敏落点（仅改值 vs 需消费方适配 vs 云端 snapshot 是否需重导）；③ 形成脱敏方案送人工决策。交付物：影响面核查记录 + 脱敏方案（本规格 §2 内联，必要时另出方案稿归项目目录）。

## 2.2 影响面

| 维度 | 改动 |
|------|------|
| 前端/客户端 | 可能改动：grade-insight 渲染读取身份信息字段处，须确认占位值显示不破版（AC2） |
| 服务端 | 可能改动：`netlify/functions/grade-store` 云同步含姓名字段，须确认兼容（AC3） |
| 数据模型 | 值变更（不改 schema）：`exam.json` / `正式档案` 身份信息字段值 → 占位 |
| 对外接口/第三方 | 无改动（本地数据 + 自有云同步） |
| 安全（鉴权/密钥/数据） | 改善：减少未成年人身份信息明文暴露；处理在本机 + 清单内服务；明文不入提示词/日志/回执 |

## 2.3 数据与接口变更

仅改值不改字段名/结构。须核查消费方（`data.js` / `store.js` / `grade-store`）对占位值的兼容性；`grade-store` 云端 snapshot 若含姓名，脱敏后须评估是否重新导入以消除云端明文（属数据出境/云端一致性判断，AC3）。

## 2.4 安全与合规自检

- ☑ 不涉及密钥/凭证进入代码或提示词。
- ☑ 不涉及数据出境：处理在本机 + 当前 IDE 内置允许清单内服务完成，与 SPEC-009 同一通道。
- ☑ 不涉及生产数据破坏性操作：本地个人项目数据、纯值替换、git 可逆。
- ⚠ 涉个人敏感数据（未成年人身份信息）：处理方向为**脱敏（降低暴露）**；明文不得写入提示词/日志/回执；**不代改 git 历史**。
- ☑ 权限模型无放宽。

## 2.5 回滚方案

纯值替换、git 可逆（revert 本规格提交即回到脱敏前）。若涉 `grade-store` 云端 snapshot 重导，须先本地留存原值备份（**不入库**，仅回滚用）以便恢复。本阶段（L2 方案）无不可逆变更；实施风险与回滚随实施任务落地时执行。
