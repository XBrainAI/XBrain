# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

成绩追踪站目前把全部档案数据（学生信息、科目配置、历次考试分数与排名）保存在打开页面的那台浏览器本地：换设备、清浏览器数据即失，唯一的跨设备手段是"设置页导出快照文本 → 手工替换数据文件 → 提交仓库 → 等待重新部署"的手工流程（js/data.js 头注释、store.js 导出函数可证），超过两周未导出会提醒备份。单用户家庭场景下该流程依赖人的自觉，一旦遗忘即面临真实成绩丢失；且多设备打开永远读到各自本地的旧数据。

另一个并存的隐私面：站点密码门是纯前端校验（密码明文放在静态配置文件内、登录比对在浏览器完成），静态托管下绕过页面直接抓取数据文件即可拿走全部内容；一旦按手工流程把真实成绩提交进仓库，git 历史将永久可抓（data.js 头注释已自认此风险）。当前仓库内为演示数据（sample: true），暂无存量泄露。

结论方向已经用户确认（2026-10-11 会话）：采用部署平台 Netlify 自带的服务端能力（Functions + Blobs）做云端同步存储——不引入第三方云、不自建服务器；拒绝过"Git API 自动提交快照"与"第三方 BaaS"两条路径。

相似既有规格互链：SPEC-2026-0002（grade-insight 三页信息架构重构，in-progress——本规格不改其交付的信息架构与界面骨架）、SPEC-2026-0001（grade-insight 评审缺陷修复，in-progress——本规格不回退其修复的录入校验行为）。本规格与二者范围互斥：只新增云端同步层，不动呈现层与既有录入行为。

## 1.2 目标用户与场景

家庭成员：在一台设备考后录入成绩，此后任何设备打开站点（通过既有密码门后）都直接看到最新档案；数据不再依赖"记得手工备份"。

## 1.3 业务价值与成功指标

现状 = 首次观测（2026-10-11）：跨设备同步依赖手工导出-替换-提交流程，无自动化手段；云端无任何数据副本。指标：部署后，录入动作完成到云端出现对应数据的延迟不超过数秒；两周后回访云端存在与日常使用一致的完整档案（判定口径见 AC8）。

## 1.4 用户故事

- P0 作为家长，我希望录入保存后数据自动存到云端，以便换设备打开即最新，不必手工备份。
- P0 作为家长，我希望数据不在公开仓库历史里，以便真实成绩不会因备份动作而可被任意抓取。
- P1 作为家长，我希望设置里能看到同步是否正常、最近同步时间，以便放心依赖它。
- P1 作为家长，我希望断网或同步失败时本地功能完全不受影响，以便录入永不因网络被阻塞。

## 1.5 验收标准（可验证）

- **AC1**（行为型）Given 已通过站点密码门登录 When 在任一设备录入并保存考试 Then 本地立即可见（行为与现状一致），且随后数秒内云端档案出现该数据；换另一设备打开站点并通过密码门 Then 自动呈现云端最新档案，无需任何手工导入。验证方式：用户演示（双浏览器实测）。
- **AC2**（行为型）Given 云端尚无档案（首次使用）When 打开站点 Then 本地已有数据自动上传完成云端初始化；Given 云端已有档案 When 打开站点 Then 页面展示的档案与云端一致（本地较旧时以云端为准重渲染，本地较新时自动把较新内容送上云端）。验证方式：自动化（脚本探测）+ 用户演示。
- **AC3**（行为型）When 打开设置弹层 Then 可见同步状态（最近一次成功同步时间；最近一次失败提示）与两个手动操作："把本地数据存到云端""用云端数据恢复本地"。验证方式：用户演示。
- **AC4**（边界型）Given 未携带通行凭证或凭证错误 When 直接请求云端读写 Then 被拒绝且响应不返回任何档案内容。验证方式：自动化（node 单测 + 实际请求探测）。
- **AC5**（边界型）Given 云端已有比提交方更新的档案（以档案自带修改时间为准）When 提交写入 Then 写入被拒绝并收到冲突提示，本地数据不丢失、不覆盖，可经 AC3 的手动操作取得云端最新。验证方式：自动化（node 单测）。
- **AC6**（边界型）Given 云端档案损坏或缺字段 When 加载 Then 按既有数据兜底规则补全/回落，页面不白屏不报错。验证方式：自动化（node 单测）。
- **AC7**（行为型·回归保护）Given 既有功能 When 执行本地 file:// 调试、快照导出/导入回环、录入校验（含同日同名拦截）、既有密码门登录 Then 行为与改造前一致；node --check 与全站回归（test:repo）全绿。验证方式：自动化。
- **AC8**（交付后复核型）样本范围=生产站点常用设备（≥2 台）；判定口径=部署满 7 日时，云端档案的考试条目数与最近一次考试分数与常用设备一致；闭环时点=部署后第 7 日复盘并回写 5.2。验证方式：事实核证。

## 1.6 体验意图

同步对主路径完全无感：录入、查看、图表行为零变化；唯一的界面新增在设置弹层内（同步状态一行 + 两个手动按钮）。文案基调与站点一致（克制、家庭向）。失败不打断录入——本地永远是第一落点。

## 1.7 非目标（本期明确不做）

- 不改既有密码门的登录流程与配置文件格式（不做密码门本身的强化——把校验整体移入服务端属独立规格）。
- 不做多人/多学生档案（云端单档案）。
- 不做字段级冲突合并与冲突编辑界面（冲突口径见 AC5：整档案按修改时间新者胜）。
- 不做断网重试队列与后台自动重传（失败经 AC3 状态可见 + 手动操作兜底）。
- 不删除既有"导出快照/导入快照"与 data.js 手工备份能力（保留为离线备份手段）。
- 不改 localStorage 的键与数据结构（本地缓存语义不变）。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

新增一个 Netlify Function 作为唯一服务端端点（`netlify/functions/grade-store.mjs`，Functions v2 API），用 Netlify Blobs（`getStore({ name: 'grade_insight', consistency: 'strong' })`，单键 `snapshot`）存整档案快照 JSON（schema 1，与既有快照载荷同构 + lastModified）。@netlify/blobs 为 Functions 运行时内置能力，不新增 npm 包；netlify.toml 显式声明 functions 目录。

鉴权（裁决点，见 2.4）：GET/PUT 均要求请求头 `X-GI-Auth: <sha256hex(密码)>`；Function 运行时按请求 Host fetch 站点自身 `/auth.config.json` 取密码计算期望哈希后等值比对（Node crypto，不引入新凭证、不硬编码、无环境变量密钥）。前端从既有 brand/auth.js 登录成功后的 session（localStorage）中取已存 passwordHash 作请求头，不重算、不落新存储。

前端 store.js 改造：save() 本地照写（即时/离线优先）后异步 PUT；load() 本地立即返回 + 后台 GET，按 lastModified 新者胜重渲染；云端无数据时自动上传初始化；PUT 携带本地 lastModified，云端较新则返回 409+云端快照，前端 toast 提示且不动本地（AC5 口径）。app.js 设置弹层新增同步状态行与两个手动按钮；file:// 协议直接跳过远端同步。

## 2.2 影响面

| 维度 | 改动 |
|------|------|
| 前端/客户端 | 改动：grade-insight/js/store.js（新增同步层）、grade-insight/js/app.js 与 index.html（设置弹层同步状态）、css（少量状态样式） |
| 服务端 | 新增：netlify/functions/grade-store.mjs（+可测纯逻辑模块）；netlify.toml 增加 functions 配置 |
| 数据模型 | 无变更（快照 schema 1 原样；lastModified 字段已有，新增语义仅"同步冲突判据"） |
| 对外接口/第三方 | 新增一个同域服务端端点（GET/PUT 快照），平台能力为 Netlify 自带，无第三方服务 |
| 安全（鉴权/密钥/数据） | 新增端点请求级凭证校验（定性见 2.4）；不引入任何新密钥/凭证；真实成绩不再需要进 git 历史 |

## 2.3 数据与接口变更

- 新增接口：`GET/PUT /.netlify/functions/grade-store`（同域、请求头携带通行哈希）。GET 返回快照 JSON 或 404（空）；PUT 返回 200 / 401（凭证不符）/ 409（云端较新，附云端快照）/ 400（载荷不合规）。
- 本地数据结构、存储键、导出/导入格式均不变。

## 2.4 安全与合规自检

- ☑ 不涉及新密钥/凭证进入代码或提示词（复用既有 auth.config.json，无环境变量、无 token）
- ☑ 不涉及数据出境新增面（数据存于站点既有托管方用户自有账号内；相比现状"可抓静态文件/公开 git 历史"，档案可读面收窄为"通过密码门+携带凭证的请求"）
- ☑ 不涉及生产数据操作与存量迁移（远端为纯新增存储；本地数据不动）
- ⚠ **裁决点（意图评审裁定）**：Function 侧校验是否构成"鉴权核心逻辑（C2→L4）"。本规格定性为**不构成**：既有认证模块（brand/auth.js）零改动，登录流程不变；新增的仅是端点请求级等值校验（哈希比对），凭证材料与强度均与既有前端密码门相同（该门本为防误入级——密码明文可读于静态配置）。若评审改判为命中 C2，则本规格升级 L4，端点校验部分转人工实施。**此裁决须在 5.1 留痕后方可开工。**

## 2.5 回滚方案

单提交 git revert 即整体回滚：Function 随部署消失，前端退回纯本地存储（键与结构未变），云端残留数据无害（可在 Netlify 后台清除）。无数据迁移、无不可逆动作。
