# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

用户指令原话："[四季景点](./四季景点/) 将延吉候选方案编制为四季酒店子站"（"四季酒店"按上下文判读为"四季景点"的笔误）。上下文：延吉春节六日游候选方案文稿已由 SPEC-030 交付（三方案 A 市区慢住／B 延吉＋长白山／C 延吉＋边境线、气候与适老可行性、往返交通、用车、点位档案、住宿、餐饮、装备、费用、风险，55 条来源）；现需把它编制为四季景点的攻略型子站页面并接入门户卡片。行程**尚未圈定、未执行**，页面是规划页（无游记节、无"已完成"印章）。

现状核验（2026-11-26）：① `四季景点/` 下无延吉子站目录；`四季景点/index.html` 的 `SITES` 数组无对应条目；② `src/site-template.html` 已在 SPEC-029 完成媒体规则同步（min-width:0／contain 封面／全屏灯箱三件套，TD-015 闭环），新页直接可用；③ 开工钩子命中两条 open 待办——**TD-021**（模板移动端字号与触控目标未达标，触发时机"下次用 src/site-template*.html 新建子站页面之前"）与 **TD-023**（规划型模板无游记页的门控脚本触发回归死锚点，触发时机"下次用 src/site-template.html 建行程未执行且无游记节的页面之前"——本页精确命中）。

相似规格互链（背景证据，不承其范围）：SPEC-030（本次出行的候选方案文稿，本规格消费其内容，不重做调研）；SPEC-029（余荫山房子站——最近的同范式先例：同步后模板派生、方案可切换可深链、行程未执行无游记节、去门控脚本、页内补触控目标、验收后推送，本规格沿用其全部既定做法）；SPEC-013（清远佛冈子站）；SPEC-019（惠东子站——L1 子站改动先例）。各规格目的地与内容均不同，经 km 裁定另立本规格。

## 1.2 用户确认记录（2026-11-26 会话，AskUserQuestion 实答）

- **规格绑定与级别**：实答"另立新规格·L1"——按常规开发处理，实现后由用户验收。
- **模板待办处置（TD-021／TD-023）**：实答"照 SPEC-029 先例处理"——TD-021 只在新页面内补触控目标样式（≥44×44）不动模板；TD-023 去掉门控脚本（补游记时从模板取回）。两条均在本规格 5.2 留痕并回写 TD，TD 本身留 open 待后续统一根治（TD-023 根治路径仍待用户裁定）。
- **配图**：实答"免费图库真实照片"——子站规则模式 E：Pexels／Unsplash 等免费图库的真实摄影作品（冰雪／长白山／朝鲜族民俗主题），CC0 或免版税协议、非 AI 生成，入库前压缩、中文描述名命名、与页面描述场景吻合。
- **页面口径**：实答"保留适老内容"——适老对比、否决条件、老人票价优惠为决策核心依据，页面保留；沿用家庭称谓（爸／妈／哥／弟），无姓名等个人信息。

## 1.3 目标用户与场景

页内读者（家庭成员）：出行决策与出发前在手机上打开子站，看三方案怎么选、多冷、怎么去、花多少、带什么，按表推进圈定。门户访客：在四季景点入口页看到这张卡片并进入。行程未执行：页面是候选方案规划页，出行后按 §8.1 一把过流程补游记与实拍、打印章、门户 hasLog。

## 1.4 业务价值与成功指标

现状 = 首次观测（2026-11-26）：延吉子站 0 个；SITES 无条目。指标：① 子站页面 1 个并接入门户；② 方案 A／B／C 可切换可深链；③ 配图全部为免费图库真实照片且入库合规；④ 仓库回归测试全绿；⑤ 390×844 视口实测无横向溢出。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

三步：

1. **图源获取与入库**：从 Pexels／Unsplash 检索下载真实摄影作品——主题：长白山冬季（天池／雪林／雾凇）、朝鲜族民俗（建筑／韩服／打糕）、冰雪活动（雪圈／冰灯）、延吉城市夜景（霓虹招牌）、东北冬季美食（冷面／烤肉，食物图须与延吉菜式吻合）。下载后用 Pillow 压缩入库（`ImageOps.exif_transpose()` → 长边 ≤2048 LANCZOS → Q85＋4:2:0，不写任何 EXIF），中文描述名命名，存于子站目录按点位分子目录，一张作主图（`index.*`）、另存封面 `index.html.jpg`。图注标图库名。
2. **子站页面编制**：复制同步后的 `src/site-template.html` 到 `四季景点/延吉春节六日游/index.html` 组装——保留并改写速览／总览／方案／人文背景／营业时间复核／天气（气候）评估各节，**删除游记与美食发现两节及其导航项、连同门控脚本**（TD-023 既定路径，头注写明补游记时从模板取回），新增用车／住宿／装备／费用／风险节（沿用模板卡片语言与节骨架）；行程方案做成可切换的 A／B／C（缺省 B 推荐方案），每个方案含逐日骨架总表；点位总览按核心点位建 spot-card（各带 `.spot-hours` 行与媒体组件）；页内补充触控目标 ≥44×44 样式（照 SPEC-029 余荫山房子站的"本页补充"段移植）；内容取自 SPEC-030 交付物。餐饮节 id 避开 `food`（门控脚本已去，仍避免与既有钩子冲突）。
3. **门户接入**：`四季景点/index.html` 的 `SITES` 数组追加一条（`hasLog: false`、`date: ''`、`updated: '2026-11-26'`、封面指向子站封面文件、卡片描述含计划出行窗口）。

验证手段（同 SPEC-029，不引入新依赖）：本机 Chrome 无头模式四视口截图 + 只读测量脚本（横向溢出、图片比例、灯箱三态、触控目标尺寸）；仓库回归 `npm run test:repo`。

关键决策点：
- **规划页三方案**：方案区缺省激活 B（推荐），`#planA`／`#planB`／`#planC` 深链载入即激活。
- **适老内容保留**（1.2 实答）：速览含否决条件，方案对比含适老列，点位卡含适老星级。
- **配图为图库模式 E**：无在库实拍，出行后按 §8.1 流程以实拍替换。
