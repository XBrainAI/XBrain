# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

考试数据分析体系（SPEC-002）阶段 0+1 已交付并经用户开闸（2026-10-23"继续执行"，闸口承接留痕 AUDIT-005 处置行）。本规格承接**阶段 2（站点融合）**最小完整切片：让 grade-insight 站点能吃下 gi-exam-data/1 的档案层数据（L1+L3 入快照，E1 裁定），并在考试详情中呈现知识点画像与题级明细/错题本联动（L2/L4 经 dataRef 懒加载静态 exam.json，不进快照）。手工录入档案（无 kps/dataRef）与演示种子行为保持原样——兼容矩阵在 UI 的体现是"没有就不显示"。

相似规格互链（背景证据，范围以本规格为准）：SPEC-002（体系方案，§六阶段2 即本规格）、SPEC-003（契约与转换器 v1 已交付）、SPEC-001（导入包格式先例——本规格升级其 10 月件至 v2）、SPEC-2026-0006（云同步链路——本规格不改其网络行为）。

## 1.2 目标用户与场景

家长/学生：打开站点导入 10 月正式档案后，点击该考详情即见九科成绩 + 知识点掌握画像（薄弱标红、重点标星）+ 题级丢分明细与错题解析链接。

## 1.3 业务价值与成功指标

标准化数据首次贯通到"看得见"：站点从只有分数升级为"分数+知识点+错题入口"。指标：10 月档案导入后详情弹层三块内容正确渲染，手工/演示场景零回退。

## 1.4 用户故事

- P0 作为家长，我希望在站点上看懂"哪掌握得不行"而不只是分数，以便决定先补什么。
- P0 作为家长，我希望错题能一键点开对应的解析页，以便孩子复盘不用翻文件夹。
- P0 作为家长，我希望没这些数据的考试（手工录入）一切照旧，以便系统不被强加结构。

## 1.5 验收标准（可验证）

- **AC1**（行为型）store.js `normalizeExam` 对 `subjects[].kps`（kpId/name/rate/wrong/key/category 六字段保真）与 `exam.dataRef` 透传：导入→状态→导出 data.js 文本 roundtrip 无损；不含这两项的既有档案（演示种子/手工/中考式录入）行为与改前一致。验证方式：自动化（新增静态测试 + 全站回归）。
- **AC2**（行为型）10 月正式档案导入包升级 v2：各科合入 exam.json 的 kps（数学 51/生物 21 条，值逐条一致），考试记录含 `dataRef: "details/高一/上学期/10月/data/exam.json"`；parseImportText 可解析。验证方式：自动化（生成脚本断言 + node 校验）。
- **AC3**（行为型）考试详情弹层：该考任一科有 kps 时显示"知识点掌握"块（掌握率升序、<60% 标红、key 标★、category 页签归属、含"数据源仅××科提供"覆盖声明）；无 kps 整块不出现。验证方式：浏览器实测（本地服务）。
- **AC4**（行为型）有 dataRef 时弹层懒加载 exam.json：显示题级丢分表（科×题号，score<point 判为错题并链 analysisRef 静态 md）；fetch 失败仅提示不阻塞其余内容；无 dataRef 不发起请求。验证方式：浏览器实测 + 控制台无错误。
- **AC5**（边界型·回归保护）云同步网络行为与 grade-store 端点零改动；`node tests/run.js` 全绿；演示种子打开站点行为与改前一致。验证方式：自动化 + git diff 边界（netlify/ 不动）。

## 1.6 体验意图

详情弹层从上到下是"成绩→知识点→错题"的漏斗；无数据不空占位；标红/标星克制（只标薄弱与重点）。

## 1.7 非目标（本期明确不做）

- 跨考核踪/老化告警/补救清单（阶段 3，需 ≥2 考数据才有意义）。
- 图表化知识点雷达（先表格诚实呈现）。
- 部署发布与云端写入（沿用既有通道）。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

`store.js`：normalizeExam 增 kps/dataRef 透传（schema 编号不动，缺字段即 undefined，老数据天然兼容）；`app.js`：openExamModal 在总分口径后追加知识点块（快照内 kps）与异步 `qzBox`（fetch dataRef → 题级表+错题解析链接，encodeURI 路径）；导入包 v2 由一次性 node 生成（读 exam.json 合入），存同一文件（SPEC-001 交付物就地升级，5.2 注明）；新增 `tests/static/gi-exam-v2.test.js`（vm 沙箱 roundtrip + 缺省兼容）。

## 2.2 影响面

grade-insight/js/store.js、js/app.js（渲染追加，不改既有分支）、details/…/正式档案 JSON（数据件升级）、tests 新增；netlify/ 与同步网络代码不动。→ L1

## 2.3 数据与接口变更

快照内 exam 新增可选字段 kps/dataRef（向后兼容，旧端读不到即忽略——store 两端同一文件，服务端 grade-store 不解析内容，仅存 JSON，无接口变更）。

## 2.4 安全与合规自检

渲染全走既有 esc()；analysisRef 链接仅站内相对路径（生成时校验前缀 `md/`）；个人数据暴露面延续既有裁定不新增。

## 2.5 回滚方案

三文件 git 还原（未提交状态下即工作区丢弃）；导入包 v2 退回 v1 版本由脚本幂等再生产。
