# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

SPEC-007 评估（报告 v2，`docs/ui/XBrain-UI重构评估报告.md`）经 AUDIT-006 独立复核**有条件通过**，核心结论成立：全站 UI 零共享机制、品牌壳在 56 个文件内联重复（~O(10KB)/页）、文章页导航 5 种形态并存、模板演进无法回灌（0816 落后 16 行、0823 落后 95 事实行——raw diff 123 行、其中皮肤轴约 10 行，AUDIT-007 K1 统一口径）、3 个内容页整页异色 + query-system 整站品牌割裂。

km 于 2026-10-24 会话确认**目标扩展**（覆盖 SPEC-007 路径 A"产物像素不变"的原前提）：
1. 以 **frontend-design skill** 为实施方法（两遍法设计流程 + 反 AI 化校准清单 + 质量底线）；
2. 边界改写为"**IP 要素不变 + 壳内质感升级**"——Logo 四件套、`--xb-*` 色值、Noto 字体族、12/8/4px 圆角语义不动，排版层次/间距韵律/微交互/组件质感允许重制；
3. 目标三件：**避免 AI 化、提升质感与交互、移动优先**（手机端为第一公民）**且兼容 PC 端**（桌面为增强档，非缩放）；
4. D1–D5 决策点随本规格评审一并裁定（缺省采 AUDIT-006 回执建议），并新增 D6/D7（见 2.1 决策点表）。

相对 SPEC-007 路径 A 原案的**三处调整**（km 已确认）：①共享层本体即按 frontend-design 标准重制的升级版，非旧代码搬运；②样板波先行（3–5 页定调 → km 双端验收 → 批量）；③验收口径从"逐像素相同"改为"IP 断言 + 质感验收抽查 + 截图留档"。

相似规格互链（背景证据，范围以本规格为准）：**SPEC-007**（全站 UI 评估——本规格承接其全部结构诊断与路径结论）、SPEC-2026-0002（grade-insight IA 重构先例——本规格判定该站已达标不动）、SPEC-005（弹层标签化与移动适配先例）。本规格不承其任何范围。

## 1.2 目标用户与场景

- **手机端读者（主场景）**：km 及家庭成员，在手机上浏览频道文章/生活记录、使用工具站——单手可达、触控舒适、滚动与导航不卡顿；
- **PC 端读者（增强场景）**：桌面阅读宽度、hover 反馈、键盘导航；
- **站点所有者 km**：维护品牌壳/新增页面成本从 O(56) 降为 O(1)，规范由门禁锁定而非人工纪律。

## 1.3 业务价值与成功指标

现状 = SPEC-007 报告 v2 基线（2026-10-24）。成功 = ①共享层建成且存量页完成内联→引用迁移（品牌壳修改成本 O(1)）；②样板波经 km 双端验收、全站质感统一提升且不落 AI 模板特征；③P0 品牌风险清零（死链/Logo 违规/viewport/异色页）；④迁移页移动优先达标（对齐 grade-insight 范本）。实施不产生数据/schema 变更。

## 1.4 用户故事

- **P0** 作为站点所有者，我希望全站在 IP 要素不变的前提下完成质感升级与结构共享化，使品牌壳演进成本降为 O(1) 且视觉不落 AI 模板。
- **P0** 作为手机端读者，我希望任何页面在手机上字号、触控（≥44px）、滚动与导航都舒适，不需要横向缩放或够不着入口。
- **P1** 作为 PC 端读者，我希望桌面获得阅读宽度、hover 与键盘导航的增强，而非手机布局的简单放大。
- **P1** 作为站点所有者，我希望新页/新频道以引用式接入共享层，合规由 S3 门禁自动锁定。

## 1.6 体验意图

深色品牌基调上，以排印层次、间距韵律与真实内容质感替代模板化装饰；动效克制（每页一个编排瞬间）；手机端为第一公民（触控/单手/滚动优先），PC 端为增强档（阅读宽度/hover/键盘导航）。

## 1.7 非目标（本期明确不做）

- 不改 IP 四锚点要素（Noto 字体族、`--xb-*` 色值、Logo 四件套构成、圆角层级语义与滚动淡出行为语义）——质感升级边界以 **AC3 断言**为准：四锚点锁定，胶囊壳样式值（阴影/毛玻璃等）允许按 AC2 设计计划升级；
- 不引入构建框架/运行时依赖（路径 B 为远期选项，C3 零新增）；
- 不动 grade-insight（AUDIT-006 K9 证实已达标，D4 缺省）；
- 不重构 query-system 信息架构（仅品牌接入与移动适配；整站深色化为阶段 5b、可按工作量拆分后置）；
- 不做内容创作/文案重写（frontend-design 写作原则仅约束新增 UI 文案）；
- 内容频道站密码门问题不入本规格（独立事项，TD-003 登记）。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

**共享层结构**（路径 A 升级版）：
- `brand/tokens.css`：双层令牌——品牌层 `--xb-*` 九变量**原值平移**；皮肤层 `--skin-accent` 系与品牌层显式映射（终结 `--xb-accent` 被皮肤覆写的劫持，花都-new 模式迁移）；新增排印 scale、间距、阴影/毛玻璃、动效曲线 token；
- `brand/brand.css`：品牌壳（Logo 胶囊样式、top-nav 三件套）重制版——行为与 IP 断言不变，质感按设计计划升级；
- `brand/brand.js`：滚动淡出（`ratio*0.7` 语义不变）、`setActiveNav`、渐入编排收敛（IntersectionObserver 逐卡渐入 → 每页一个编排瞬间）。

**frontend-design 嵌入**：每波迁移执行两遍法——第一遍产出该波 token 应用与版式计划（对齐 tokens.css），第二遍对照反 AI 化校准清单（暖米底+赤陶、近黑底+酸性绿、SaaS 卡片套件、ALL-CAPS 眉标、中点 meta 串、'→' 按钮等 tells）复查后实施；质量底线（移动响应、键盘 focus、reduced-motion、可访问对比度）为硬要求。
