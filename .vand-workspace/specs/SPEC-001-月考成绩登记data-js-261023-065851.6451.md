# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

10 月月考分析材料已由 SPEC-000-月考图片转写markdown-261022-173142.5431 转写为可检索文本（`grade-insight/details/高一/上学期/10月/md/`），九科分数、满分与班级等级均有出处；但 grade-insight 登记数据（`js/data.js` GRADE_SNAPSHOT）内仍只有 `sample: true` 的演示种子，含一条同名"高一上第一次月考"假记录（分数与真实完全不同）。用户指示不手动填报、直接把解析所得成绩登记入本地系统（2026-10-23 会话指令）。

**已呈报并由用户裁定的风险**（详见 5.1）：真实个人成绩提交进 git 后永久可抓、且随静态站点发布不受密码门保护（SPEC-2026-0006 §1.1 自认的隐私边界）。用户在知情呈报后仍选择"提交进仓库 data.js"路径；本规格承载该裁定留痕。

相似规格互链：SPEC-000（数据来源：10 月月考图片转写——背景证据，范围以本规格为准）；SPEC-2026-0006（云端同步存储——本规格不改其代码与链路，仅改种子数据）。用户裁定另立新规格，不挂靠 0006。

## 1.2 目标用户与场景

家长/学生本人：打开 grade-insight（新设备/清档后）即以真实第一次月考为登记起点，趋势图不再混入演示假分数。

## 1.3 业务价值与成功指标

登记数据从演示态切换为真实态。指标：GRADE_SNAPSHOT 内考试记录与 10 月解析 md 逐科一致、总分自洽、无演示数据残留。

## 1.4 用户故事

- P0 作为家长，我希望 10 月月考九科成绩自动登记入系统，以便免去手动填报且后续分析基于真实数据。
- P0 作为家长，我希望登记值与原始图片解析结果可追溯一致，以便有疑问时能回查出处。

## 1.5 验收标准（可验证）

- **AC1**（行为型·v2 修订）`details/高一/上学期/10月/正式档案-高一上第一次月考.json` 存在且可被站点导入逻辑解析（parseImportText→JSON），内含且仅含一条真实考试记录"高一上第一次月考"（type 月考、term 高一上），九科 score/full/level 与 `details/高一/上学期/10月/md/` 各科成绩概览及总分概览一致（语文 111/150 B、数学 80/150 D、英语 64.5/130 D、物理 66/100 C、化学 46/100 D、生物 64/100 C、政治 59/100 D、历史 64/100 C、地理 69/100 无等级），且各科之和 = 623.5 与总分自洽；`js/data.js` 与 HEAD 一致（演示原样，diff 为空）。验证方式：自动化（node 加载断言 + git diff）。
- **AC2**（边界型）图中未提供的字段（班级/年级均分、排名、总分年级排名）留空不编造；考试具体日期 raw 未确认（仅知 10 月），按 2026-10-10 暂记并在 note 声明"日期为月份暂记待确认"。验证方式：自动化 + 用户确认日期后修订。
- **AC3**（行为型·回归保护）站点既有功能不受损：`npm test`（vitest）与既有静态测试（含 gi-store-sync.test.js）全绿；store.js 初始化逻辑对新种子无异常。验证方式：自动化。
- **AC4**（交付后复核型）样本范围=用户常用设备打开的生产/本地页面；判定口径=用户阅读趋势页确认成绩与图一致；闭环时点=用户反馈即修订。验证方式：用户复核。

## 1.6 体验意图

登记后站点首屏即真实档案：一条月考记录、九科可画趋势；演示数据（摸底考/期中/期末等 2025 假日期记录）整体退役，不残留半真半假档案。

## 1.7 非目标（本期明确不做）

- 不执行 git commit/push（等用户评审后另行指示）。
- 不改 store.js/grade-store 同步链路代码（仅改数据种子）。
- 不做云端远端写入（真实数据进云端的通道仍是既有浏览器录入/同步链路）。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述（v2 修订：交付物改为正式档案导入包，data.js 演示种子不动）

交付 `grade-insight/details/高一/上学期/10月/正式档案-高一上第一次月考.json`：站点"设置→导入数据"可直接载入的 JSON 快照（schema 1，student=〈姓名〉/enrollYear 2026，subjects 默认九科，exams 仅一条真实月考：九科 score/full/level 按 10 月 md 转写件，均分/排名留空，日期暂记 2026-10-10 并在 note 声明）。导入即被 store.js:246 importSnapshot 置 `isSample:false` 并触发既有同步链路自动上传云端——"正式数据入云"经由浏览器导入动作完成，仓库侧 data.js 保持演示原样（store.js:264/273 演示档案永不上传；sample 为档案级标志，故正式数据不能混入演示种子，此为本路径的机制依据）。

## 2.2 影响面

新增一个数据文件（details/高一/上学期/10月/ 下 JSON）；不改代码、不改 data.js、无接口与依赖变更。→ L1

## 2.3 数据与接口变更

GRADE_SNAPSHOT 内容由演示样本切换为真实快照（schema 版本 1 不变）。

## 2.4 安全与合规自检

真实个人成绩与姓名的 git 入库风险已向用户书面呈报（本规格 1.1/5.1），用户显式裁定接受；不含密钥凭证。呈报未获裁定前不落笔（已获）。

## 2.5 回滚方案

git 工作区未提交前直接还原 data.js 即可；提交后回滚需 revert（历史暴露面不可逆——已在裁定中告知用户）。
