# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

阶段 2 上线后用户对"高一上第一次月考"详情提出四项体验反馈（2026-10-23 会话）：① 错题本解析跳转打开的是 markdown 原文，学生无法阅读，要求改 HTML；② 弹层整体垂直深滚动、交互不便；③ 问年级均分/相对均分/年级排名能否由等级说明.md 反推估算；④ raw 原图的分数仪表盘直观，要求纳入；综合=单次月考分析直观化不足。

请求方对③的技术答复（已获用户默认、经 AskUserQuestion 无涉及项默认承接）：**不可反推**——等级说明只含个人等级↔得分率区间，年级分布量不在其中，估算即编造（R6 假精确红线）；诚实路径=准入清单增"各科成绩概览·年级视图"补录项，10 月可补拍重入。用户对①②裁定（AskUserQuestion 原话）：解析 HTML 化=**"预渲染（推荐，需批 devDeps）"**（即批准 C3 依赖变更：markdown-it+KaTeX 仅 devDependency，产物为自包含静态 HTML，站点运行时零新增依赖）；布局=**"弹层分页标签（推荐）"**。

相似规格互链（背景，范围以本规格为准）：SPEC-004（阶段2 弹层与错题本——本规格是其体验迭代，不改其数据链）、SPEC-003（流水线与固化件——新增预渲染工序与裁剪件）、SPEC-002（体系方案，R6/版本纪律依据）。

## 1.2 目标用户与场景

学生/家长：点开一次月考，第一屏见九科仪表盘原图；四个标签页平级切换（仪表盘/题级错题/知识点/环比），不再深滚；错题"解析"打开的是排版可读、公式可渲染的 HTML 页。

## 1.3 业务价值与成功指标

价值：把"数据都在"升级为"一眼看懂、点得动"。指标：56 份解析 HTML 全生成且抽查可读；弹层一屏内完成四区切换；九科仪表盘图在位。

## 1.4 用户故事

- P0 作为学生，我希望错题点开是能读的解析页（公式正常显示），以便直接复盘。
- P0 作为家长，我希望单考第一屏就是各科分数与等级的直观仪表，以便快速定位问题科目。
- P1 作为家长，我希望年级数据以真实补录替代估算，以便趋势对比可信。

## 1.5 验收标准（可验证）

- **AC1**（行为型）`pipeline/render-analysis.js`（devDeps：markdown-it+katex，outputType=svg）把 10 月 56 份试卷解析 md 预渲染为自包含 HTML 至 `details/<考>/data/analysis/`（公式内联 SVG、配图相对路径可达、内嵌基础样式）；错题本"解析"链接改指该 HTML（路径按约定从 analysisRef 推导），点击新标签打开可读页面。验证方式：脚本自检（数量/大小/含 svg 断言）+ 浏览器实测。
- **AC2**（行为型）考试详情弹层改为四标签页：📊仪表盘（默认页：总分仪表盘图+各科仪表盘图+成绩表）/ 📋题级错题 / 🧠知识点 / 📈环比与总分；标签栏固定、页内有限高滚动，整层不再深滚。无仪表盘图/无 dataRef/无 kps 时对应区自动退化为文字表格（手工档案零回退）。验证方式：浏览器实测 + 控制台无错。
- **AC3**（交付物型）九张仪表盘裁剪 PNG（总分+8 科，地理源缺注明）落 `details/<考>/data/assets/`，边界完整（含分数大字/满分/等级标尺，不混入导航与题目表），执行方回读自检留痕。验证方式：人审图样。
- **AC4**（交付物型）准入清单 v1.1 增补"各科成绩概览·年级视图"可选补录项与用途说明（年级均分/排名真实来源）；DATA-CONTRACT.md 同步登记 dashboard/analysis 路径约定（v1.1，向后兼容不改 schema）；converter 元数据 acceptance 版本随之更新。验证方式：文档审 + 重跑 convert 对账回归（既有数值零漂移）。
- **AC5**（边界型·回归保护）站点运行时零新增依赖（index.html/js 引用不变，无 CDN）；npm 仅 devDependencies 增两项；云快照与已导入档案不受影响（本规格不触发再导入）；`node tests/run.js` 全绿。验证方式：git diff 边界 + 回归。

## 1.6 体验意图

第一屏=仪表盘原图带（点击可放大看原图区），信息密度对齐原平台；标签平级、零嵌套滚动。

## 1.7 非目标（本期明确不做）

- 不做年级数据的任何估算/模拟（红线）。
- 不改数据 schema、不改同步链路、不触发云端重写。
- 独立单考报告页（用户裁定选弹层方案）与阶段 3 联合分析不在本规格。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

render-analysis.js：markdown-it(html:false 安全默认)+katex 占位替换（$…$/$$…$$→renderToString output:'svg'），图片 src 重写为 `../../md/images/…` 相对路径，输出内嵌 CSS 的自包含 HTML；命名约定 `<科>-试卷解析-<N>.html`（去空格括号），前端由 analysisRef 同规则推导。app.js：openExamModal 重构为标签容器（复用现有 modal，注入 tab bar 与四个 pane，页内 max-height 滚动）；仪表盘 img 路径由 dataRef 目录推导 `data/assets/<科cn>-仪表盘.png`，onerror 退化隐藏。裁剪件由后台子代理按固化纪律产出（v2 交付留痕记录 y 范围）。

## 2.2 影响面

app.js（弹层结构）、新脚本、数据目录新增 assets/analysis 静态件、两个文档 v1.1、package.json devDeps。不改 store/同步/schema。→ L1（C3 依赖变更已由用户裁定批准，5.1 留痕）

## 2.3 数据与接口变更

路径约定扩展（非 schema）；exam.json/快照内容不变。

## 2.4 安全与合规自检

预渲染关闭 html 直通（防 md 内注入）；分析页仅静态本地资源；无外部请求。

## 2.5 回滚方案

删 assets/analysis 目录、还原 app.js/两文档/package.json 即可。
