# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

用户在会话中完成了 11 家候选酒店的多维度决策分析（口径：近景点>方便活动>环境卫生>档次；2 大 2 小；结合 SPEC-018 核实坐标实测车程与 2026-11 套餐价），并要求"简化为一页纸的 html，嵌入景点方案中"。现状：`四季景点/惠东周末家庭游/index.html` 的「酒店推荐」节只有逐家卡片，缺一张全家可同览的横向对比与裁决入口。

相似规格互链（背景证据，不承其范围）：SPEC-019（决策地图嵌入先例——纯新增节+双导航入口模式）、SPEC-018（H1–H11 编号体系与坐标/车程数据源）、SPEC-008（卡片/断点规范）。

## 1.2 目标用户与场景

全家人围屏（或打印一页）共同裁决"住哪家"：先看一页纸对比表 + 三个打包选项直接投票，需要细节再往下翻逐家卡片。

## 1.3 业务价值与成功指标

现状 = 首次观测（2026-11-17）：页面无酒店横向对比表。指标：新增一节含 ① 11 家 × 6 维度精简对比表（含 H# 与决策地图互引）② 3 个裁决选项 ③ 秋冬/预算两条提示 ④ 数据口径脚注；桌面一屏内可纵览（约 ≤1.5 屏）；页面其余节零改动。

## 1.4 用户故事

- P0 作为家人，我希望一页看到全部候选的关键差异（价格/离海龟湾/玩水/卫生/两案适配），以便快速锁定 2-3 家。
- P0 作为家人，我希望有现成的打包选项（方案+酒店+总价）直接投票，以便不用逐项自己组合。
- P1 作为家人，我希望知道数字口径（车程怎么算的、价格什么时段），以便放心采信。

## 1.5 验收标准（可验证）

- AC1（行为型）：Given index.html When 导航点「选型决策」Then 定位到 #hotel-decision 节，桌面导航与移动下拉各一条入口。【验证方式：grep 断言 + 浏览器目检】
- AC2（行为型）：Given 该节 When 渲染 Then 对比表 11 行齐全（H1–H11 与决策地图编号一致），列含：一晚总价(4口)/离海龟湾车程/沙滩玩水星级/卫生口碑/适配A/适配B；下方含 3 个裁决选项与 2 条提示、1 条口径脚注。【验证方式：grep 断言 + 目检】
- AC3（边界型）：Given ≤640px 窄屏 When 查看 Then 对比表可横向滚动不撑破布局、选项卡单列堆叠。【验证方式：390px 目检】
- AC4（边界型）：Given 页面其余节 When 对比提交前后 Then 除两处导航新增行与新节外零改动。【验证方式：git diff 零删改】

## 1.6 体验意图

一页纸=信息密度高但扫读友好：表格星级一眼分高下、三个选项像"投票卡"；沿用全站卡片语言与 H# 互引；打印时该节自成一块。

## 1.7 非目标（本期明确不做）

- 不改「酒店推荐」既有卡片内容（一页纸是它的总览前置）；
- 不引入新 CSS/JS 依赖、不做交互筛选；
- 不更新 方案.md；不改动决策地图。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

纯静态插入，复用既有类：在 `<!-- ===== 6. 酒店推荐 -->` 之前插 `<section id="hotel-decision">`：section-desc（口径一句话）→ `.table-scroll` 内 `.plan-summary-table` 11 行对比（H#/候选/一晚4口/离海龟湾/沙滩玩水★/卫生★/适配A/适配B★短评）→ 三个选项用 `.hotel-grid` 三卡（组合/一晚价/适合谁/一句话）→ `.tips-box` 两条提示 → `.img-credit` 口径脚注 → backtop。导航两套在「营业时间」后各加「选型决策」。数据取会话分析结论（车程=坐标×道路系数估算；价=2026-11 错峰套餐口径）。
