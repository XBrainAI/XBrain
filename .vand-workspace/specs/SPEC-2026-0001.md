# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

2026-09-30 对 `grade-insight` 子站（家庭高中成绩跟踪分析）完成全面评审，结论为"本体可上线"，但存在 2 个 P2 缺陷与 5 个 P3 缺陷；同日发现仓库回归门禁存在 3 项存量红项（由 2026-09 末"西樵山游记"提交引入，已推送远端）。按仓库 harness 纪律"回归不全绿禁止推送"，红项会阻塞下一次任何推送。

- P2-1 导入崩溃：若导入的考试记录所有科目均无得分（全缺考），成绩总览与智能简报在渲染时崩溃（页面空白仅余错误提示）。页面录入路径有校验拦截，但导入路径无此校验，脏数据可进入本地档案。
- P2-2 静默覆盖：以相同日期与相同名称新建考试时，查重校验失效，旧记录被无声覆盖。成绩属家庭隐私且无服务端备份，静默丢数据不可接受。
- P3 组：导入非数字得分产生 NaN 污染分析；示例数据状态下出现无意义的备份提醒横幅；趋势页分科数据点在同日两场考试时可能错位；首考对比的科目范围口径判断过弱；一段永不生效的死代码。
- 回归红项：`四季景点/佛山西樵山石燕岩周末家庭游/游记/解惑-探秘-科普.html` 缺首屏锚点与品牌组件（IP 规范硬性要求）；`_hevc_originals_20260920/` 存档含 5 个 HEVC 编码视频（Chrome/安卓不可播，违反媒体三重防线），且该存档未被任何页面引用。

## 1.2 目标用户与场景

家庭成员（家长录入、孩子查看）在浏览器使用成绩追踪站：导入别处导出的成绩备份、逐场录入考试、查看趋势分析。红项场景：访客从四季景点导航进入科普页时看到一致的品牌与返回体验；仓库维护者推送任何改动时门禁应当可信。

## 1.3 业务价值与成功指标

现状 = 首次观测（2026-09-30）：回归门禁 31 用例中 3 失败；grade-insight 存在 2 个可致渲染崩溃/静默覆盖的缺陷。成功指标：回归门禁 0 失败；上述缺陷在验收场景下不再复现且无新缺陷引入。

## 1.4 用户故事

- P0 作为家长，我希望导入的备份文件即使含"全缺考"考试也能正常打开档案，以便坏数据不至于让整个分析不可用。
- P0 作为家长，我希望重复录入同日同名考试时被明确拦截，以便不会在不知情中丢掉已录成绩。
- P1 作为家长，我希望导入文件里的乱值不会污染趋势图表，以便分析始终可信。
- P1 作为访客，我希望从科普页看到与其他四季景点页一致的品牌组件并可返回导航。
- P1 作为仓库维护者，我希望推送前门禁全绿，以便部署纪律可信。

## 1.5 验收标准（可验证）

- AC1（行为型）Given 本地档案中存在一场所有科目均无得分的考试（经导入进入） When 打开总览与各视图 Then 页面正常渲染（空态或明确提示），无崩溃报错，其余功能可用。验证方式：自动化（页面脚本探测）+ 用户演示。
- AC2（行为型）Given 已存在某日期+名称的考试 When 以相同日期与名称新建考试并保存 Then 保存被拦截且提示重复，旧记录数据保持不变。验证方式：自动化（页面脚本探测）。
- AC3（行为型）Given 编辑既有考试且未更改日期与名称 When 保存 Then 正常更新且不误报重复。验证方式：自动化（页面脚本探测）。
- AC4（边界型）Given 导入内容含非数字得分（如字母串） When 执行导入 Then 无 NaN 进入分析序列（无效值按缺考处理或导入被拒），趋势与图表渲染正常。验证方式：自动化（页面脚本探测）。
- AC5（行为型）Given 档案处于内置示例数据状态 When 查看横幅 Then 不出现"建议导出备份"提醒。验证方式：自动化（页面脚本探测）。
- AC6（行为型）Given 同一天存在两场不同考试且某科仅在其中一场有分 When 查看趋势页该科曲线 Then 该科数据点与其发生的考试一一对应，无错位。验证方式：事实核证（构造用例核对）。
- AC7（行为型）Given 首考与最近一次考试的科目集合不同但数量相同 When 生成智能简报 Then 显示"科目范围不同，对比仅供参考"提示。验证方式：事实核证。
- AC8（行为型）Given 访客打开解惑-探秘-科普.html When 检查页面结构 Then 页面含首屏锚点与完整品牌组件（品牌图形、品牌文字 X/Brain 结构、返回链接目标存在）。验证方式：自动化（回归套件 S3.x）。
- AC9（边界型）Given 仓库发布树 When 扫描全部视频 Then 不存在 HEVC 编码视频；被移出的 5 个原片在本仓库之外保留文件副本，且 git 历史仍可追溯。验证方式：自动化（S7.1）+ 事实核证。
- AC10（行为型）When 运行全站回归与语法检查 Then 全部用例通过（0 失败）且 grade-insight 全部脚本语法有效。验证方式：自动化。
- AC11（行为型·回归保护）Given 示例数据档案 When 执行六视图切换、密码认证、导出导入回环 Then 行为与修复前一致（导出导入核心数据无损）。验证方式：自动化（页面脚本探测）。

## 1.6 体验意图

grade-insight 修复均为异常场景下的行为纠正，正常路径交互与视觉不变；新增的唯一可见变化：重复录入被拦截时的提示文案、坏数据场景的空态/提示文案。解惑页新增品牌组件视觉与同游记首页一致（绿色系品牌胶囊，固定左上角），不改动该页既有内容与配色。

## 1.7 非目标（本期明确不做）

- 不修改认证模块（brand/auth.js）与任何站点密码/会话逻辑。
- 不对 HEVC 原片做转码（原片保持原始编码，仅移出发布树）。
- 不修改 grade-insight 示例快照数据内容与数据结构定义（schema 不变）。
- 不涉及 query-system 与其他子站的任何改动。
- 不执行推送部署（推送 = Netlify 生产发布，属 L3，由人工另行触发）。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

全部为最小侵入修复：① 分析层与总览渲染在"无可计分考试"序列时提前返回空态（消除崩溃）；② 录入校验引入"编辑排除 id"参数，使同日同名查重对新建场景生效、编辑自身正确豁免；③ 数值规范化统一用有限数校验，非有限值归null（按缺考口径）；④ 备份提醒跳过示例档案；⑤ 趋势页分科序列改为按考试一一映射（与总分同序），不再按日期字符串匹配；⑥ 首考对比口径改为科目 key 集合比较；⑦ 清理死代码；⑧ 解惑页按同游记首页模板补品牌 CSS/HTML/滚动淡出脚本与首屏锚点；⑨ 将未被引用的 HEVC 原片存档目录整体移出仓库（至仓库外本地备份目录），文件本体保留。选择"移出"而非"转码"：原片价值在于原始编码，压缩可播版本均已在库且被页面引用，git 历史亦保留副本，信息零丢失。

## 2.2 影响面

| 维度 | 改动 |
|------|------|
| 前端/客户端 | 改动：grade-insight 三个脚本（分析/存储/应用层）与四季景点一个静态页（补品牌与锚点） |
| 服务端 | 无改动（纯静态仓库） |
| 数据模型 | 无改动（schema=1 不变；仅对脏值做防御性归null） |
| 对外接口/第三方 | 无改动 |
| 安全（鉴权/密钥/数据） | 无改动（不触碰认证模块）；媒体文件移出为仓库卫生操作，文件保留于本地与 git 历史 |

## 2.3 数据与接口变更

无 schema/接口变更。内部校验函数新增可选的"编辑排除"参数，唯一调用方同步更新。

## 2.4 安全与合规自检

- ☑ 不涉及密钥/凭证进入代码或提示词
- ☑ 不涉及数据出境（工作由 ZCode 会话内完成，不向外部服务发送仓库内容）
- ☑ 不涉及生产数据操作（媒体移出保留副本与历史；无用户数据删除）
- ☑ 权限模型无放宽（未触碰认证）

## 2.5 回滚方案

代码改动均为普通文件编辑，`git revert` 单提交即可整体回滚；媒体目录移出为可逆操作（目录整体保留于仓库外备份路径，历史版本可 `git checkout` 恢复）。无数据迁移，无反向迁移需求。
