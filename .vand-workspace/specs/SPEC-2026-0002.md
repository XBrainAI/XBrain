# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

用户试用示例数据后提出四点反馈：① 智能简报为整段文字，不直观；② 多数图表缺少图例与"怎么读"的口径说明（单科小图、迷你图无轴无标注，榜单只有数字）；③ 页面间图表与结论重复（总览迷你走势≈趋势折线、总览强弱科≈科目偏科榜、简报文字复述所有图表数字）；④ 六个 Tab 的分叉结构不符合"打开→看现状→看变化→知道下一步"的直线阅读路径。

根因是信息架构按功能模块组织而非按阅读顺序组织：高频路径被拆在总览/趋势/科目三个页，证据（图表）与结论（简报）分离。

## 1.2 目标用户与场景

家庭成员打开成绩追踪站：考后录入一次，平时打开快速看完"现在什么水平、和上次比怎样、哪科要抓、下一步做什么"。

## 1.3 业务价值与成功指标

现状 = 首次观测（2026-09-30）：完成"读完一遍报告"需要在 3 个 Tab 间跳转且简报为纯文字墙。指标：报告页一屏到一页内直线读完，无跨页跳转；图表均有图注。

## 1.4 用户故事

- P0 作为家长，我希望打开应用后从上往下滚一遍就能看完"本况→要点→走势→学科→目标"，以便不用在页面间跳。
- P0 作为家长，我希望先看到 3-5 张一句话要点结论（可点击跳到对应图表），以便 10 秒抓住重点；完整文字简报折叠收起、随时可复制给 AI。
- P0 作为家长，我希望每张图表都有一句话说明口径与看法，以便不用猜数字含义。
- P1 作为家长，我希望录入和考试明细在同一页完成，以便记录动作不换页。
- P1 作为家长，我希望低频的设置不占底部导航，以便主路径更聚焦。

## 1.5 验收标准（可验证）

- AC1（行为型）Given 打开应用 When 观察导航 Then 底部仅两个主 Tab（报告/记录），设置经右上角齿轮弹层可达；旧深链 #overview/#trends/#subjects/#exams/#entry/#settings 均自动重定向到对应新位置（含章节定位/展开录入/打开设置弹层），不出现空白页。验证方式：自动化（页面脚本探测）+ 用户演示。
- AC2（行为型）Given 示例数据档案 When 自上而下滚动报告页 Then 依次呈现：本况 KPI → 本期要点卡 → 总分走势与相对年级位置 → 学科诊断（雷达+偏科榜+单科折叠走势） → 目标与提分优先级 → 完整简报（折叠），全程无跨页跳转。验证方式：用户演示。
- AC3（行为型）When 查看任一图表或榜单 Then 均有一句话图注说明口径/单位/看法；单科走势默认折叠、展开时才绘制图表。验证方式：事实核证 + 页面脚本探测。
- AC4（行为型）Given 数据 ≥3 场 When 打开报告页 Then 要点卡 3-5 张、每张点击滚动到对应章节；Given 数据不足 Then 对应章节显示"数据不足"提示而非空白或报错。验证方式：自动化（页面脚本探测）。
- AC5（行为型）Given 记录页 When 点击"＋ 录入新考试" Then 表单展开；保存/取消后收起回到考试时间线；从考试详情弹层点"编辑"能打开同一表单并回填。验证方式：自动化（页面脚本探测）。
- AC6（行为型·回归保护）Given 既有功能 When 执行认证、录入校验（含同日同名拦截）、详情弹层环比拆解、导出导入回环、清空/载入示例 Then 行为与重构前一致。验证方式：自动化（页面脚本探测）。
- AC7（边界型）When 在 375px 视口检查 Then 无横向溢出、可点击元素 ≥44px、弹层可关闭；node --check 与全站回归（test:repo）全绿。验证方式：自动化。

## 1.6 体验意图

打开即报告：首屏是"本况 + 要点"，往下滚是证据（图表带图注），最后是目标与可复制的完整简报。要点卡是"结论先行"的入口，图表是证据，简报全文是附录。记录页动作单一（录入/翻查/编辑）。设置降为弹层但内容不减。文案基调不变（家庭向、克制、给"仅供参考"口径）。

## 1.7 非目标（本期明确不做）

- 不改数据模型、存储键（xbrain_grade_insight_v1）、快照格式与导入导出格式。
- 不改认证模块与既有分析算法口径（新增"要点提取"为只读衍生，不改变现有函数返回）。
- 不升级 echarts、不新增依赖。
- 不做主题/配色改版（沿用品牌底座与现有深色主题）。
- 不迁移 `grade-insight/AGENTS.md` 已吸收的历史原文描述（其描述的六视图属历史版本记录）。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

呈现层重构，三层不动数据与算法：① 外壳 index.html 从六视图改为双视图容器（view-report / view-records）+ 头部齿轮按钮 + 双 Tab；② app.js 路由收敛为 report/records 两条主路由 + 旧六路由别名表（映射到"路由+章节滚动/展开动作"），渲染函数重组：报告页按"本况→要点→走势→学科→目标→简报"顺序拼装（复用既有 analysis 函数与 charts 封装），记录页=录入表单（默认收起）+考试时间线，设置改为弹层复用既有 modal；③ analysis.js 新增 takeaways(state) 纯函数输出结构化要点（图标/文案/锚点），briefing() 保留原文用于折叠全文与复制。图表可读性以"每图一句话图注 + 榜单口径标注 + 单科走势 details 懒绘制"实现。取最简单可行方案：不引入新组件、新依赖、新图表类型，全部为既有积木的重新编排。

## 2.2 影响面

| 维度 | 改动 |
|------|------|
| 前端/客户端 | 改动：grade-insight 外壳、应用层（路由/渲染重组）、分析层（新增只读要点函数）、样式层（新增组件样式） |
| 服务端 | 无改动 |
| 数据模型 | 无改动 |
| 对外接口/第三方 | 无改动 |
| 安全（鉴权/密钥/数据） | 无改动（不触碰认证；页面仍受 XBrainAuth 保护） |

## 2.3 数据与接口变更

无数据变更。hash 路由对外表现变化：旧六路由保留为别名并自动重定向（向后兼容，旧深链/收藏不失效）。

## 2.4 安全与合规自检

- ☑ 不涉及密钥/凭证进入代码或提示词
- ☑ 不涉及数据出境（ZCode 会话内完成，不向外部服务发送仓库内容）
- ☑ 不涉及生产数据操作
- ☑ 权限模型无放宽

## 2.5 回滚方案

单提交 git revert 即可整体回滚；无数据迁移，localStorage 结构与键不变，新旧 UI 可互换。
