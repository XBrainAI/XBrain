# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

2026 年国庆假期（10-01~10-07）仅剩最后一天（10-07，周三，次日上班上学）。用户需求原话："国企剩余一天，挖掘其它适合的景点行程"（"国企"按上下文判读为"国庆"笔误）。家庭四人（爸驾车、妈、哥、弟）需一份从荔湾西村出发的当日自驾行程：假期尾声适合去哪、避开什么（返程高峰、黄金周人流、已去过的景点）。缺少一份候选挖掘充分、主推方案可执行的收官日规划。

相似规格互链（背景证据，不承其范围）：SPEC-2026-0003《大岗办事+南沙区图书馆自习 家庭一日行程规划（2026-10-05）》——同假期、同家庭、同交付范式（调研+方案文稿落位 `四季景点/待出行方案/`），但范围锁定 10-05 那一天（办事+自习固定日程），与本任务（10-07 开放式景点挖掘）不属同一任务，故另立本规格。

绑定与前提留痕：本任务承接时按执行约定 1 呈报了绑定裁决（另立新规格 vs 修订 0003）与出行日期确认两问，**用户未及答复**；按呈报建议选项推进——①另立新规格（最保守，不动既有规格）；②出行日期取 2026-10-07（今天 10-06、假期 10-01~10-07、0003 留痕的交警研判 10-07 有返程高峰，三者互证）。两项假设待用户确认，如有偏差在本规格 5.1 补留痕并修订。

## 1.2 目标用户与场景

家庭四人（爸驾车、妈、哥、弟，常住荔湾君荟名轩·西村地铁站上盖）：假期最后一天轻松出游一天，早出早归（回家后哥弟尚有作业/收心时间），不看夜景不赶夜路。

## 1.3 业务价值与成功指标

现状 = 首次观测（2026-10-06）：`四季景点/待出行方案/` 无 10-07 相关规划。指标：候选挖掘 ≥3 个（且不与已覆盖行程重复），主推方案时间表 07:30 出发、15:30 前回到西村且时间闭合，关键场所信息均标注来源与访问日期或"待现场确认"。

## 1.4 用户故事

- P0 作为全家，我希望拿到多个"其它适合的"候选并有一档主推，以便不用再调研即可出发。
- P0 作为全家，我希望行程避开 10-07 返程高峰（15:00–21:00 分散车流、17 时峰值），以便顺畅回家。
- P0 作为哥/弟，我希望晚上留有作业时间（15:30 前到家），以便次日上学不慌。
- P1 作为爸妈，我希望候选对比含"为何去/为何不去"与费用粗算，以便临场降级有依据。
- P1 作为全家，我希望黄金周场所开放/预约/活动信息经联网核实并标注来源，以便规避闭门羹。

## 1.5 验收标准（可验证）

- AC1（事实核证型）Given 方案定稿 When 逐条核对关键事实 Then 天气、返程研判、候选景点开放/门票/预约/停车均有带来源与访问日期（2026-10-06）的结论；无法核实的显式标注"待现场确认"并给出降级办法。验证方式：对照来源清单核查。
- AC2（行为型）Given 候选挖掘 When 阅读候选章节 Then ≥3 个候选（主推+备选+兜底三档），均不与已覆盖行程（西樵山/惠东/河源/深圳/从化吕田/白云乐8/香港/花都/古埃及展/大岗图书馆·灵山岛尖等）重复，并附排除清单说明"为何不去"。验证方式：逐档核对。
- AC3（行为型）Given 主推方案 When 阅读行程表 Then 覆盖 07:30 出发至 15:30 前回到西村，每段含车程估计且时间闭合，遵从家庭铁律 §11（早出发 07:00–07:30、早返程 14:00–15:00、避开正午暴晒、节奏悠闲）。验证方式：逐段推演时间闭合。
- AC4（行为型）Given 午餐与变化 When 查看预案 Then 主推方案给出午餐 ≥2 个具体选项，且每个不确定点有"如果……就……"预案（含天气恶化按 §13.8 户外段取消的兜底）。验证方式：逐项核对。
- AC5（边界型）Given 交付物 When 检查落位 Then 文档位于 `四季景点/待出行方案/`，命名风格与既有方案一致（.md），含日期、路线锚点、行程表、贴士、来源清单等既有章节要素。验证方式：文件检查。
- AC6（边界型）Given 家庭约束 When 通读全文 Then 不含姓名/证件/联系方式等个人敏感信息（仅"哥/弟/妈/爸"称谓），爸驾车滴酒不沾红线明示。验证方式：全文检查。

## 1.6 体验意图

一页读完、三档对比、主推可执行：出发前一晚能扫完并完成预约类准备；行程中按表推进；每个不确定点都有降级路径。

## 1.7 非目标（本期明确不做）

- 不做 HTML 页面化、不改 `四季景点/index.html` 导航、不动门户卡片（如需页面化，另立规格）。
- 不代订/代约（不实际执行门票购买、军校预约、餐厅订位），仅提供操作指引。
- 不输出实时路况承诺：车程均为静态估算并标注"以当日导航为准"。
- 不涉及出行后 `生活点滴` 补录（出行结束后另行处理）。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

交付物为单一 Markdown 文稿，融合两类既有范式：候选分析部分沿用 `桂山岛亲子自驾出行分析报告.md` 的"核心结论→可行性→家庭铁律→三档建议"结构；主推方案部分沿用 `清远佛冈自驾一日游计划.md`/`南沙大岗…一日行程规划.md` 的"路线总览→行程表→节点详解→降级预案→自驾贴士→来源清单"结构。信息获取：官方发布优先（景区官方渠道/政府网站/主流媒体），检索转述类信息标注"以官方发布为准"；家庭铁律取自 `四季景点/AGENTS.md` §11/§13.8（经桂山岛报告引用核对）。天气（10-07 晴 20~29℃）与返程研判（10-06/07 峰值、17 时峰值、北环沙贝立交等易堵段）已于 2026-10-06 联网核实。

## 2.2 影响面

| 维度 | 改动 |
|------|------|
| 交付物 | 新增 1 个 .md 文档（`四季景点/待出行方案/`） |
| 服务端/数据模型/对外接口 | 无改动 |
| 敏感与隐私 | 仅使用"哥/弟/妈/爸"家庭称谓，不含姓名/证件/联系方式等个人敏感信息 |

## 2.3 数据与接口变更

无。

## 2.4 安全与合规自检

- ☑ 不涉及密钥/凭证进入代码或提示词
- ☑ 不涉及数据出境（仅公开网页信息检索，不发送仓库内容）
- ☑ 不涉及生产数据操作
- ☑ 不含未脱敏个人敏感数据

## 2.5 回滚方案

删除新增文档即可，无其他影响。
