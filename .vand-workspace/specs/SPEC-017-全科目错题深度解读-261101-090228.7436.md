# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

用户指令（2026-11-01 原话）："【题级错题】罗列错题列表外需对各错题进行深度分析，要让考生知道考什么知识点，自己缺漏哪些知识点，如何规避复发等，数学、生物已有现成的解读，但也没达到上述要求，请对所有科目进行上述深度分析解析。"

现状 = 首次观测（2026-11-01，10 月首考 data/exam.json 实测）：7 科有题级得分，**错题共 115 道**——语文 12 / 数学 10 / 英语 36 / 物理 7 / 化学 8 / 生物 12 / 政治 15 / 历史 15；地理无题级数据（本期排除，见 1.7）。逐题解读现状：

- 数学（19/19）、生物（37/37）有逐题"试卷解析"件（题干/我的答案/参考答案/知识点标签/解析），但只有"答案对不对"视角——**没有**"这道题考什么考点、暴露我哪个知识/能力缺口、下次怎么不再错"的考生视角解读；知识点仅是标签罗列，未与掌握度对照、未给防复发动作。
- 其余 6 科**完全没有逐题解读**（题级 analysisRef 覆盖 0），错题本只能看分数与错题列表。
- 可用素材齐备：`md.纸质卷/` 有各科考卷与答案转写（语文缺答案件）、`md/〈科〉-作答原卷.md` 有学生作答转写、数学/生物另有知识点掌握度数据与已复核错因（C1–C6，22 题已确认）；渲染与站点链接路径已通用（错题本对 analysisRef 逐题开放）。

不解决的后果：错题复盘停留在"哪些题丢了分"，考生不知道每道错题对应的考点与自身缺口，无法针对性防复发，错题本沦为分数清单。

相似既有规格互链（背景，范围以本规格为准）：
- SPEC-011（考情分析体系v2——题级内容融合（错因诊断）与跨考演化，in-progress）：其错因诊断（C1–C6）、KP 掌握度与四象限是本规格深度解读的**输入证据**之一；本规格不回退其字段与视图，其结构化 cause 字段与 KP 全局字典**不扩展到其他科目**（属其范围）。
- SPEC-009（纸质卷转写markdown，in-progress）：考卷/答案/作答原卷转写是本规格的内容来源管道；其遗留疑点（数学 13/15–19 作答影像与题号疑错位）按诚实口径继承处理。
- SPEC-006（考系统分析报告，in-progress）：R1–R7 引擎结论与"未标注≠无问题"诚实声明口径延续，本规格不回退。
- SPEC-004（站点融合阶段2——知识点透传，in-progress）：其透传的 kps 字段沿用，不改动。

## 1.2 目标用户与场景

家长/学生：考后复盘时打开错题本，任一科目的任一道错题都能点开一份深度解读，三问三答——这道题考什么（考点定位）、我缺什么（缺漏诊断）、下次怎么不再错（防复发策略）；并能按科目总览"我这科到底缺哪些知识点"（缺漏汇总），据此安排重练。

## 1.3 业务价值与成功指标

价值：错题复盘从"分数清单"升级为"逐题归因 + 缺口地图 + 防复发动作"。指标（现状 = 首次观测 2026-11-01）：错题深度解读覆盖 0/115 → **115/115**；解读抽检准确率 ≥80%（口径见 AC3）；错题本逐题入口可达率 100%。

## 1.4 用户故事

- P0 作为家长，我想点开任一科目的任一道错题就看到"考什么知识点"，以便判断这道题的考察定位。
- P0 作为家长，我想在每道错题解读里看到"孩子缺漏哪些知识点/能力"，以便辅导有的放矢。
- P0 作为家长，我想看到每道错题"如何规避复发"的可执行做法（识别信号/重练动作/自查清单），以便孩子知道下次怎么办。
- P1 作为学生，我想按科目看到缺漏知识点汇总清单，以便安排复习优先级。
- P1 作为家长，我希望数学/生物的既有解读也补齐上述三段式，以便全科目标准一致。
- P2 作为家长，我希望解读里所有"预判/补注"都有口径标注（AI 生成+人工抽检、参考答案补注、数据疑点），以便不过度解读。

## 1.5 验收标准（可验证）

- **AC1**（行为型）Given 10 月首考数据 When 在错题本打开 7 科任一道错题 Then 该错题有可打开的深度解读，且三段式齐备（考点定位/缺漏诊断/防复发策略）；覆盖 = 115/115（语文 12、数学 10、英语 36、物理 7、化学 8、生物 12、政治 15、历史 15）。验证方式：脚本结构断言（文件存在 + 三段标题齐备 + 数据引用一致）+ 浏览器实测。
- **AC2**（行为型）Given 数学/生物既有 22 份错题解读 When 升级 Then 既有内容（题干/我的答案/参考答案/知识点/解析）零丢失，新增三段式；渲染重跑幂等（除时间戳外零 diff）。验证方式：升级前后内容对比 + 渲染重跑 diff。
- **AC3**（内容质量型）每份解读的考点定位须可溯源（依据题干/考卷原文与教材模块归属），缺漏诊断须引用可得证据（掌握度数据/作答对照/已复核错因），无证据处诚实标注"证据不足"；不编造参考答案——解析源受限科目（生物逐题解析"略"且无主观题参考答案）的"参考答案与解析要点"段不得复用既有解析文本、须按题干/选项语义独立撰写并带口径标注，语文无官方答案件处明示"参考答案为 AI 依据通行评分标准补注"。验证方式：用户抽检 ≥10 题（跨科目分层抽取），考点与缺漏判断准确率 ≥80%（口径同 SPEC-011 AC9：抽检合格率），反馈驱动模板修订（升版重跑）。
- **AC4**（行为型）Given 7 科 When 打开该科错题本弹层 Then 可达该科"错题缺漏汇总"（缺漏知识点清单 + 共性错因 + 防复发清单），7 科齐备。验证方式：文件结构断言 + 浏览器实测。
- **AC5**（边界型）无证据/数据疑点诚实降级，覆盖错因复核件确认的**全部**数据疑点与源限制（显式清单：数学 8 参考答案键疑点〔C6，疑答案键或转写有误〕、数学 13/15–19 作答影像疑错位、生物逐题解析源限制〔"略"且无主观题参考答案〕、语文缺官方答案件）——涉疑解读不依赖失效证据（不作答案键硬断言、不依赖失分步骤定位、不复用缺失解析）并显式标注；无作答转写的科目不虚构"我的答案"；地理无题级数据不生成解读、站点不出现空壳入口；所有解读带口径标注行（AI 生成 + 人工抽检）。验证方式：报告审 + 脚本断言。
- **AC6**（体验型·移动端）深度解读 HTML 沿既有渲染模板与样式基线：390/375/320 三档无横向溢出，家长可读语言（内部编号 C1–C6 不外露，术语通俗）。验证方式：三档测量 + 人审。
- **AC7**（回归型·零回退）R1–R7 引擎对 10 月考的判定与数字不变，node tests/run.js 全绿；exam.json 既有字段与既有 56 处 analysisRef 零破坏（新增引用走 gi-exam-data/2 既有可选字段，无 schema 变更）。验证方式：自动化。

## 1.6 体验意图

入口 = 错题本既有逐题链接位（打开即深度解读，不再只是"试卷解析"），科目弹层新增"缺漏汇总"入口（该科文件存在才显示）；空态 = 无解读的科目/题目不显示入口，不出现空壳；文案基调 = 面向考生的直接、鼓励式但不含糊——先说考什么，再说缺什么，最后给"下次怎么办"的可执行动作；术语家长可读。

## 1.7 非目标（本期明确不做）

- **地理**：无题级数据（exam.json 未录入逐题得分/题号），本期排除；题级数据补录后另启（已登记 TD，触发时机=地理题级数据录入时）。
- 做对题目的逐题解读（只做错题；既有数学/生物做对题的解读件保留不动）。
- 结构化 cause 字段与 KP 全局字典扩展到其他科目（属 SPEC-011 范畴，本规格错因分析承载于解读正文）。
- 跨考层（KP 演化/顽固薄弱）与 R1–R7 引擎改动。
- 站点信息架构/视觉体系改动（只在既有弹层与链接位内做内容级扩展）。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

内容层为主、代码层最小改动：

1. **深度解读结构模板（六段式，内联固化）**：每份错题深度解读 = ① 题干与作答对照（摘录，作答可得时）② 参考答案与解析要点（数学/生物既有件保留原文，新增科目按考卷与答案转写撰写）③ **考点定位**（本题考什么知识点、所属教材模块、能力层级——依据题干原文可溯源）④ **缺漏诊断**（该题暴露的知识/能力缺口，引用掌握度数据/作答对照/已复核错因，无证据显式标注"证据不足"）⑤ **防复发策略**（可执行：同类题识别信号、重练动作、自查清单、练习指向）⑥ 口径标注行（AI 生成 + 人工抽检；语文参考答案补注声明；数据疑点声明）。**先产 1 题风格样例经用户确认，再按科目分批批量产出**（风格锚定样例固化于 `pipeline/DEEP-REVIEW-TEMPLATE.md`，版本化 v1）。
2. **文件落位与命名**：沿既有试卷解析系列约定——数学/生物 22 道错题**就地升级**既有 `md/〈科〉-试卷解析 (N).md`（追加三段式，保留原文），其余 6 科错题**新建**同系列文件（仅错题，93 份）；缺漏汇总新系列 `md/〈科〉-错题缺漏汇总.md`（7 份）。渲染复用 `pipeline/render-analysis.js`（命名映射既有），产物落 `data/analysis/`。
3. **数据层**：exam.json 为 93 道新错题补 `analysisRef`（gi-exam-data/2 既有可选字段，无 schema 变更）；数学/生物 22 处既有 ref 不动。
4. **站点层**：`analysisHref` 链接路径已通用无需改动；错题 tab 科目弹层加"错题缺漏汇总"入口（按文件存在性显示，缺失不渲染入口）。
5. **状态快照**：产出按科目分 7 批，跨会话续作时用 progress 文件 `.vand-workspace/specs/SPEC-017-全科目错题深度解读-261101-090228.7436.progress.deepreview.json`（域=deepreview，记录已完成科目批次/待办/续作入口；单会话一次完成则免建）。
6. **疑点与源限制承接口径（AUDIT-016 条件①采纳）**：错因复核件确认的数据疑点与源限制按显式清单承接（数学 8 答案键疑点 / 数学 13/15–19 作答影像疑错位 / 生物解析源限制 / 语文缺官方答案件），处置方式 = 不作答案键硬断言、不依赖失分步骤定位、生物"参考答案与解析要点"段按题干/选项语义独立撰写（既有解析为"略"，不可复用）、语文参考答案带 AI 补注声明。模板兼容既有题头两格式（数学 `## 题号 N` / 生物 `## 第 N 题`），就地升级保留原题头。英语 36 道错题含共享阅读语篇的题组，按"语篇 → 题组"分批产出以保持考点定位一致。

## 2.3 数据与接口变更

- exam.json：7 科 93 道错题新增 `analysisRef` 字段值（gi-exam-data/2 既有 optional 字段，旧读取端全兼容）；无其他字段改动。

- 无对外接口变更。

## 2.4 安全与合规自检

- ☑ 不涉及密钥/凭证进入代码或提示词；
- ☑ 不涉及数据出境：内容生成使用本会话模型服务（允许清单内），解读素材均为已脱敏的本人家庭学业数据（承接 SPEC-010 口径），不新增身份信息；
- ☑ 不涉及生产数据操作；
- ☑ 权限模型无放宽。

## 2.5 回滚方案

内容件与 HTML 产物按提交整体回退（git revert）；exam.json 增量字段回退同提交；站点入口按文件存在性渲染——产物回退后入口自动消失，无需反向迁移。渲染重跑幂等，返工仅重生成对应科目批次。
