# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

中考志愿查询系统的用户配置——学校收藏与多批次志愿编排——只保存在打开页面的那台浏览器本地：换设备、清浏览器数据即失，现有跨设备手段是"导出配置 JSON 文件 → 另一设备手工导入"（页面已有该按钮对），依赖人的自觉，忘带文件即丢数据。

该问题与成绩追踪站改造前完全同构。成绩站已落地并经用户验证的解决方向（SPEC-2026-0006，in-progress——部署后两轮缺陷修复，服务端链路可用）为：站点部署平台自带的云端存储 + 站点密码门会话作凭证 + 本地第一落点异步镜像。用户明确要求将同一方案平移至本系统（2026-10-11 会话指令"将 query-system 的配置数据也改为上述方案"）。

一处必须补齐的差异：成绩站的凭证来自其密码门会话，而本系统当前无密码门。本规格补齐同模式子站密码门（复用既有共享认证模块与既有配置结构，不改认证模块本身；口令沿用成绩站同款、可随时改配置文件；会话有效期放宽为 30 天以降低打扰）。

相似规格互链：SPEC-2026-0006（grade-insight 云端同步存储——方案来源与先例，范围以本规格为准）；SPEC-2026-0002 不相关（成绩站界面）。

## 1.2 目标用户与场景

家庭成员（家长为主）：在一台设备编排志愿与收藏，任何其他设备打开本系统、通过密码门后即见同一份配置；不再手工导出导入。

## 1.3 业务价值与成功指标

现状 = 首次观测（2026-10-11）：配置跨设备依赖手工文件导出/导入，云端无副本。指标：部署后配置变更到云端可见延迟秒级；两周回访云端存在与日常使用一致的配置副本（口径见 AC8）。

## 1.4 用户故事

- P0 作为家长，我希望收藏和志愿编排自动同步到云端，以便换设备打开即同一份配置。
- P0 作为家长，我希望云端数据不被无关者读取或篡改，以便志愿偏好保持私密。
- P1 作为家长，我希望断网或同步失败时本地功能完全不受影响，以便编排永不因网络阻塞。
- P1 作为家长，我希望页面上能看到同步是否正常，以便放心依赖它。

## 1.5 验收标准（可验证）

- **AC1**（行为型）Given 通过密码门登录 When 在一台设备收藏学校或编排志愿 Then 本地立即生效（行为与现状一致）且数秒内云端出现该变更；换另一设备打开本系统并通过密码门 Then 收藏与志愿列自动呈现云端最新配置。验证方式：用户演示（双浏览器实测）。
- **AC2**（行为型）Given 云端无配置（首次）When 登录后打开本系统 Then 本地已有配置自动上传初始化；Given 云端有配置 When 打开 Then 页面配置与云端一致（不一致时按配置自带修改时间新者胜重渲染）。验证方式：自动化（vitest）+ 用户演示。
- **AC3**（行为型）When 打开页面 Then 可见同步状态入口，且可执行两个手动操作："上传配置到云端""从云端恢复配置"。验证方式：用户演示。
- **AC4**（边界型）Given 未携带或携带错误通行凭证 When 直接请求云端读写 Then 被拒绝且响应不返回任何配置内容。验证方式：自动化（node 单测 + 实际请求探测）。
- **AC5**（边界型）Given 云端已有比提交方更新的配置 When 提交写入 Then 写入被拒绝并收到冲突提示，本地数据不丢失，可经 AC3 手动操作取回云端最新。验证方式：自动化（node 单测 + vitest）。
- **AC6**（边界型）Given 云端配置损坏或缺字段 When 加载 Then 收藏回落为空列表、志愿回落为空编排（旧格式迁移逻辑不受影响），页面不白屏不报错。验证方式：自动化（vitest）。
- **AC7**（行为型·回归保护）Given 既有功能 When 执行收藏/志愿编排、旧版志愿数据迁移、配置文件导出/导入、密码门登录与锁定 Then 行为与改造前一致（本系统新增密码门除外）；`npm test`（vitest）与 `npm run lint` 全绿、全站回归 test:repo 全绿。验证方式：自动化。
- **AC8**（交付后复核型）样本范围=生产站点常用设备（≥2 台）；判定口径=部署满 7 日时云端配置与常用设备的收藏列表、志愿编排一致；闭环时点=部署后第 7 日复盘并回写 5.2。验证方式：事实核证。

## 1.6 体验意图

新增的密码门与成绩站同款视觉与交互（首访输一次、30 天免输）。同步对主路径无感：收藏、筛选、志愿编排行为零变化；同步状态收在页头一角（状态可查 + 两个手动按钮），失败不打断任何操作——本地永远是第一落点。文案基调与站内一致。

## 1.7 非目标（本期明确不做）

- 不改共享认证模块 brand/auth.js 本身（仅按既有模式新增一处子站接入与配置文件）。
- 不改志愿数据模型与旧版迁移逻辑（v1→v2 迁移保持原样）。
- 不做字段级冲突合并（整配置按修改时间新者胜）。
- 不做断网重试队列与后台自动重传。
- 不迁移既有 localStorage 键与结构（本地缓存语义不变）。
- 不改成绩站（SPEC-2026-0006 范围）。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

平移 SPEC-2026-0006 已验证架构到本系统，三件事：① 新增子站密码门——`query-system/auth.config.json`（结构同 grade-insight 款：enabled/password/lockout/ui，`sessionDuration: 30` days，password 初值沿用 grade-insight 同款口令、呈报时明示可改）+ vite 模板 index.html 以**绝对路径**接入 `brand/auth.css`/`brand/auth.js`（dist 位于 `/query-system/dist/`，相对路径会指错层级；`XBrainAuth.init({ level:'sub', subSiteName:'query', configPath:'/query-system/auth.config.json' })`，file:// 调试跳过沿用既有内联模式）；② 新增端点 `netlify/functions/query-store.mjs`——复用 grade-store-core.cjs（凭证等值校验、冲突判定、哈希），载荷校验内联（favorites 数组 + volunteerOrders 对象 + lastModified 字符串），Blobs 独立 store `query_system` 单键 `config`，运行时按 Host fetch `/query-system/auth.config.json` 核凭证（C2 定性沿用 SPEC-2026-0006 意图评审先例：同模块、同模式部署，非鉴权核心改造）；③ 前端同步层——新增 `src/utils/cloudSync.ts`：collect（三键汇总为配置快照 + lastModified）、去抖 2s push、pullSoon（未登录不消耗对账标记；云端空且有本地数据则初始化上传；本地为空则直接采用云端；lastModified 新者胜；409 提示不覆盖）、状态与手动上传/恢复；filterEngine.ts 全部写入口（setVolunteerOrder/setBatchVolunteerOrder/setFavorites/toggleFavorite/importConfigFromFile/migrateOldVolunteerData）成功写本地后调 schedulePush；App.tsx 监听 `qs:remote-applied` 事件 bump favoritesVersion 触发重渲染（既有机制），页头加同步状态入口与两个手动按钮。

## 2.2 影响面

| 维度 | 改动 |
|------|------|
| 前端/客户端 | 改动：query-system/src/utils/cloudSync.ts（新增）、filterEngine.ts（写入口挂钩）、App.tsx（状态入口 + 事件联动）、index.html 模板（密码门接入）；不提交 dist/（部署时构建） |
| 服务端 | 新增：netlify/functions/query-store.mjs（复用 grade-store-core.cjs） |
| 数据模型 | 无变更（localStorage 三键不变；云端为新增快照存储） |
| 对外接口/第三方 | 新增一个同域服务端端点（GET/PUT 配置快照），平台能力为 Netlify 自带 |
| 安全（鉴权/密钥/数据） | 新增子站密码门（既有共享模块按既有模式接入）+ 端点请求级凭证校验（定性见 2.4）；不引入新密钥/凭证 |

## 2.3 数据与接口变更

- 新增接口：`GET/PUT /.netlify/functions/query-store`（同域、请求头携带通行哈希）。GET 返回配置快照 JSON 或 404（空）；PUT 返回 200 / 401（凭证不符）/ 409（云端较新，附云端快照）/ 400（载荷不合规）。
- 本地数据结构、存储键、导入/导出格式均不变。

## 2.4 安全与合规自检

- ☑ 不涉及新密钥/凭证进入代码（密码配置文件沿用既有明文口令模式，防误入级；无环境变量）
- ☑ 不涉及数据出境新增面（存于站点既有托管方自有账号内；志愿/收藏不含个人身份信息，受密码门+凭证双重保护）
- ☑ 不涉及生产数据操作与存量迁移（云端为纯新增存储）
- ⚠ **C2 定性沿用 SPEC-2026-0006 意图评审先例（2026-10-11，"按 L2 实施"）**：既有共享认证模块零改动，本规格仅按同一既有模式接入子站 + 端点请求级等值校验。若评审改判为命中 C2，则升级 L4，密码门接入与端点校验转人工实施。**此裁决须在 5.1 留痕后方可开工。**

## 2.5 回滚方案

单提交 git revert 即整体回滚：端点消失、密码门移除（页面恢复免密直开）、前端退回纯本地存储（键与结构未变）。云端残留配置无害（可在 Netlify 后台清除）。无数据迁移、无不可逆动作。
