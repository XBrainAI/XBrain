# 一、Requirements（产品视角 · 意图作者填写）

## 1.1 背景与问题

用户原话："游记 分析图片与视频，识别蕴含的动植物人文等事物，并做相关的历史、科普介绍，编制一份介绍文档，供后续编制游记做扩充延展性参考以丰富游记内容。"

**现状核验（2026-10-31 实测）**：

- 素材落位 `四季景点/清远佛冈周末家庭游/游记/`，共 **39 个文件**：35 张图片（jpg，含 1 张行车记录截屏）+ 4 段视频（mp4），为 2026-10-31 当日实拍（观音山王山寺 09:13–09:51 → 路边稻田 10:30 → 上岳古村 10:54–11:50 → 713 行车记录 21:02 截屏）。〔v2 修订：初稿按会话附件目录清单计 42（37 图+5 视频），实施中 `Get-ChildItem` 实测为 39（35+4），附件清单含 3 个实际不存在的项，以实测为准〕
- 文件名已含人工标注线索：菩提树（标称 2600 年）、螺、飞蝶、猫、晒禾秆草、晒谷、古士多、镬耳元素、佛冈IP、诸事皆宜、向阳而生、觅食、流水、稻田兄弟、713 行车记录等。
- 子站现有 `index.html`（攻略型页面，SPEC-013 产物）与 `上岳古村/`、`观音山王山寺/` 图集目录；`游记/` 目录**尚无 README 与科普参考件**。
- 项目既有要求（project-context §13.5 / §11.6）：人文/历史/非遗/宗教/地质类景点**必须**补充面向孩子的背景解说；西樵山先例已在游记补齐"科普图解"。

后果：游记编制时若无系统化的识别与考据底稿，动植物与人文事物只能凭印象描述，历史与科普内容无法保证事实准确（尤其寺龄/树龄、村史年代、物种判定这类易错点）。

相似规格互链（背景证据，不承其范围）：SPEC-012（行程候选分析，交付物为行程文档）、SPEC-013（子站攻略页面，其 §1.6 明确"不做游记模块，出行后另轮补充"）、SPEC-2026-0005（候选挖掘范式）。本任务产出物为**独立的备考参考文档**，不在上述任何规格范围内，经用户裁定（2026-10-31 会话）另立本规格。

## 1.2 目标用户与场景

- **游记编制会话/编制人（主要）**：后续编制 `游记/README.md` 与游记页面时，按主题条目直接取用经过核证的物种名称、历史年代、民俗解释与"讲给孩子听"的表达素材。
- **家庭成员（间接）**：阅读丰富、准确且有延展知识的游记内容。

## 1.5 验收标准（可验证）

- AC1（行为型·事实核证）Given 参考文档 When 逐条核对 Then 每个条目含：识别结论、知识介绍（历史/科普）、游记可用素材（可直接引用的细节或讲解话术）、关联素材文件清单；关键事实（年代、名称、数据）附来源与访问日期，无法核证者显式标注"待核证/推测"。
- AC2（行为型）Given 39 个素材文件（以编制时点实测清单为准并随文档固定；后续新增素材不溯及本规格）When 检查引用 Then 全部文件至少被一个条目的素材清单引用（同场景重复图/视频可归并至同一条目，不得遗漏文件）。
- AC3（边界型·事实核证）Given 动植物识别条目 When 审阅 Then 物种结论以图片/视频帧可见特征为依据，给出不确定度表述（如"疑似/依据特征判定"），不把猜测写成定论。
- AC4（边界型）Given 文档全文 When 检查 Then 符合仓库既有红线：仅用"哥/弟/爸/妈"家庭称谓，无真实姓名；车牌号仅保留既有文档已出现的"713"简称、不新增完整牌照信息；不含可导出个人行踪的精确住址。
- AC5（边界型）Given 落位与格式 When 检查 Then 文档为单个 Markdown 文件，位于 `四季景点/清远佛冈周末家庭游/游记/资料-动植物与人文科普备考.md`（命名沿用既有"资料/说明"类文档风格），不修改 `index.html`、不改动素材文件本体。

# 二、Design（技术视角 · Conductor 填写）

## 2.1 方案概述

三段式产出：

1. **素材识别**：逐张 Read 35 张图片（视觉识别物种、建筑构件、民俗场景、文字标牌）；4 段视频用本机 ffmpeg 各抽 2–3 帧代表性画面后 Read 识别（抽帧临时件放 `.screenshots/.tmp/`，用后清理，不入库）。
2. **知识考据**：对识别出的事物按主题聚类（上岳古村建筑与村史、观音山王山寺与菩提树、稻田生态与物种、晒谷/晒禾秆草民俗、佛冈在地文化等），用 WebSearch/WebFetch 核证关键事实，官方渠道与地方志/文物部门来源优先，检索转述类标注"以官方发布为准"；每条来源记录访问日期（2026-10-31）。
3. **文档编制**：单 Markdown 文件，按**事物主题**组织条目（非按文件罗列），每个条目三段结构（识别结论 / 知识介绍 / 游记可用素材）+ 关联素材清单；文末附「素材 → 条目」反向索引保证 AC2 全覆盖，及「待核证清单」汇总不确定项。

## 2.2 影响面

| 维度 | 改动 |
|------|------|
| 交付物 | 新增 1 个 .md 文档（`四季景点/清远佛冈周末家庭游/游记/`） |
| 前端/服务端/数据模型/对外接口 | 无改动 |
| 素材文件 | 零改动（只读分析） |

## 2.3 数据与接口变更

无。

## 2.4 安全与合规自检

- ☑ 不涉及密钥/凭证。
- ☑ 不涉及数据出境（仅公开检索核证，不向外部服务提交个人敏感数据；图片不上传外部服务，识别在会话内完成）。
- ☑ 不涉及生产数据；素材只读。
- ☑ 个人敏感信息按 AC4 口径自检（称谓、车牌、住址）。

## 2.5 回滚方案

单文档新增，`git revert` 或直接删除即可；无不可逆变更。
