# 过程待办登记区（todos）

> 任务过程中产生的**规格外待办**（不紧急、不堵塞当前任务、但需在合适时机处理：外部依赖、经确认延后的项、
> 时机性协作等）登记在此——不依赖任何会话的记忆，随项目 git 跟踪。例行钩子（见范式入口
> "过程待办登记区与会话例行钩子"节）：开工前扫到期待办 → 过程中产出即登记 → 收尾列报全部 open 条目与外部依赖、
> 承接对账（『转 TD-〈编号〉』声明逐一对账，未兑现 = 欠账）。
> 规格任务表内的任务不在此登记（规格是任务的家）。本文件由 init 创建：只补缺不覆盖，条目不删除（就地回写状态留痕）。

## 登记约定

- 条目编号 `TD-<年份>-<四位序号>`，全局顺延、不复用；每条一个 `###` 小节，追加在"待办条目"节末尾。
- 登记与回写一律用**增量编辑**（精确匹配锚定后插入/改行），**禁止凭上下文旧副本整文件覆写**，写后回读确认条目仍在（多会话同工作树防静默丢失）。
- 编号分配：登记前**重读本文件**取最大号 +1（不凭记忆）；发现撞号（同号两条）→ 后写者就地改号并留痕。跨 clone/分支合并冲突按条目级行合并——双方条目都保留，同条目状态行冲突以回写留痕时间先后为准。
- 字段行（小节首行）：状态｜触发时机｜来源｜登记日期。
- **触发时机必须写可判定的条件**（会话据此判断何时呈报）：日期（`日期 2026-10-20 到达`）、规格节点
  （`SPEC-2026-0012 进入实施前`）、版本节点（`v2.10.0 发布前`）、任务节点（`任务 X 合并前`）、
  项目接触（`下次在项目 Y 开工时`）；无自动时机的写 `manual`（仅随收尾钩子呈报）。
- 状态：`open`（待办）/ `done`（完成）/ `cancelled`（取消）——就地回写并追加一行回写留痕（日期 + 结论），
  **条目不删除**（留痕即历史）。
- **跨条目转移（承接闭环，v2.10.0）**：在回写行或产出物中声明『转 TD-<编号>』『另立 TD 条目』时，承接条目**当场增补**——
  写明对应处理项并加 `- 承接自：` 字段行指向来源（TD 号或产出物路径）；未兑现的转移声明由 todos_lint 门禁（ci/scripts/todos_lint.py）报**欠账**。
- 登记内容遵守项目既有红线：密钥凭证与未脱敏的客户/个人敏感数据不入库。
