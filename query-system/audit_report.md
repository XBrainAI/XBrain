### 2.4 [WARN] 名额分配控制线（2026）数据存在差异

**问题描述**：`2026年广州市普通高中名额分配录取最低控制线.md` 中部分学校名称与系统内部名称不一致，依赖 `clNameMap` 硬编码映射。

**具体案例**：

| MD文件中的名称 | 系统映射后的名称 | 状态 |

| 广州市第六中学（海珠校区） | （无映射，使用原名） | [OK] 但系统库中可能为"广州市第六中学" |

**审核结论**：
- `parseQuotaControlLines` 解析出 109 所学校控制线数据
- `dataMerger.ts` 中 `clNameMap` 仅列出约 24 所学校，其余学校通过 `find(r => r.schoolName === mappedName)` 匹配
- 若 MD 中名称与 `schoolLib` 中名称不完全一致（如括号差异），可能导致 `xieheControlLine2026` 无法正确关联

### 2.10 [WARN] 学校名称匹配存在潜在风险

`extractBaseName` 函数用于去除括号内容后进行模糊匹配：
```typescript
function extractBaseName(fullName: string): string {
  let name = fullName
    .replace(/\s*（[^）]*）\s*/g, '')
    .replace(/\s*\([^)]*\)\s*/g, '')
    .trim();
  if (name.length < 4) name = fullName;
  return name;
}
```

**潜在问题**：
- `广州市第六中学（海珠校区）` → `广州市第六中学`
- `广州市第六中学（从化校区）` → `广州市第六中学`
- 两者去括号后相同，若同时出现在不同数据源中，可能产生匹配混淆
- 但当前数据中 `广州市第六中学（海珠校区）` 和 `广州市第六中学（从化校区）` 在学校库中分别独立存在，匹配逻辑通过完整名称优先，风险可控

## 四、问题汇总与修复建议

### [FAIL] 问题1：补录数据完全丢失

**根因**：`parseMakeupScores` 要求 `学校编码` 和 `学校名称` 同时存在，但 `补录分数-2025.md` 无 `学校编码` 列。

**修复建议**：修改 `parseMakeupScores`，移除对学校编码的强制要求：
```typescript
const name = row['学校名称'] || '';
if (!name || name.includes('正常录取')) continue;
// 移除对 code 的强制检查
```

### [WARN] 问题2：2026控制线名称映射不完整

**根因**：`clNameMap` 仅硬编码24所学校，其余依赖精确名称匹配。

**修复建议**：
- 方案A：扩展 `clNameMap` 覆盖全部109所学校
- 方案B：在 `dataMerger.ts` 中使用 `extractBaseName` 进行模糊匹配

### [WARN] 问题3：`districtQuota` 与 `provinceQuota` 值相同

**根因**：`parseXieheQuota2026` 将同一数值同时赋给两个字段。

**修复建议**：若未来需要区分省市名额和区属名额，应分别读取 `省市名额` 和 `区属名额` 列。当前显示逻辑只使用 `provinceQuota`，不影响结果。
