# 四季景点 · 子站模板（src/）

> 本目录存放「四季景点」新子站的**可复用 HTML 模板**。
> 经 2026-08-10 评审，定下两套互补模板；候选 B（kit/ 片段包）、候选 C（site-template-themed.html）与 `CANDIDATES.md` 已清理。

## 两套模板：何时用哪个

| 模板 | 文件 | 定位 | 适用场景 |
|------|------|------|----------|
| **攻略 / 规划型** | `site-template.html` | ⭐ 8 段结构、多方案切换、营业时间复核、天气评估 | 陌生 / 远 / 复杂、需**提前规划**的出行（周末家庭游、多方案亲子游） |
| **纯游记 / 记录型** | `site-template-travelogue.html` | 轻量：总览 → 实录 → 美食 → 实用信息 | **熟悉 / 去过 / 近 / 简单**、事前不规划、事后记录游记 |

> 判断口诀：要「提前规划方案」→ 攻略型；只是「走完记一笔」→ 纯游记型。

## 文件导航

| 文件 | 作用 |
|------|------|
| `site-template.html` | 攻略/规划型正式模板（单文件综合蓝本）；**内置游记核心模块**，位于「行程方案」之后 |
| `site-template-travelogue.html` | 纯游记/记录型模板（暖色皮肤，轻量结构）；其游记核心与攻略型同源 |
| `site-template-travelogue-core.html` | ⭐ **游记核心模块（公共单一来源）**：`.log-chapter` + `.food-card` 的 CSS/HTML/JS，被以上两个模板共同引用 |
| `assets/ph1..6.svg` | 占位图，演示主图+缩略图切换；预览用，正式子站须替换为真实图片 |
| `assets/index.svg` | 首图占位演示图（命名 `index.*` 会被自动选为主图）；正式子站用它替换成你自己的 `index.*` 或直接删掉 |

## 配图组件通用规则：首图自动解析（index.* 优先，缺失回退）

两个模板的 `.media-block` / `.culture-card` / `.timeline-content` 共用同一套画廊逻辑：

- **数据源是画廊**：每个需要图片的卡片，把该卡片对应的「图片文件夹里的全部图片」列进 `.media-gallery`（含 `index.*` 若有）。
- **首图自动选**：JS 加载时自动解析主图（`.media-cover`）——
  - 画廊中**命名 `index.*` 的图优先作主图**（无论扩展名：index.jpg / index.png / INDEX.webp 都认）；
  - 若**漏命名 `index.*`**（常见），**回退为画廊第一张**作为主图——兼容缺失，不会空白；
  - 想指定别的图当首图又不想命名 index：把它调成画廊第一张即可。
- **不重复展示**：当前主图会从缩略图条隐藏；点击任意缩略图即切换为主图（原主图重新回到条中）。
- **单图场景**：画廊只有一张图时，缩略图条自动隐藏，仅显示主图。
- **切换不丢首图**：`index.*` 缺失时仍按第一张稳定展示，作者无需手动维护封面 src（封面 src 由 JS 写入，HTML 里的占位 src 会被覆盖）。

> 直接改 HTML 里 `<img class="media-cover">` 的 `src` **不会**生效——首图由 JS 从画廊推导。要定首图，请在画廊里正确命名 `index.*` 或调整顺序。

## 一、攻略 / 规划型（site-template.html）

1. 复制 `site-template.html` → `四季景点/<新子站>/index.html`。
2. 把 `assets/ph*.svg` 换成真实图片：把该卡片的主图命名 `index.*` 放进画廊首位（不命名也会自动取第一张），其余图按展示顺序放入 `.media-gallery`，图片与 `index.html` 同目录。
3. 按 `{{...}}` 占位符填：hero、行程速览、景点卡、方案、人文卡、营业时间、酒店、天气、贴士。
4. **换肤**：只改 `:root` 的 `--accent` / `--accent2` / `--hero-grad` 三处。
5. 顶部导航首条为 `← 返回`（`../index.html`）。
6. **游记模块（默认内置）**：「行程方案」之后已预置 `#log` 游记实录 + `#food` 美食发现两段（含示例 `.log-chapter` / `.food-card`）。制定方案并执行后，直接在此填写真实行程即可，无需改动结构；其源码来自 `site-template-travelogue-core.html`，请勿本地另写一份。

结构（8 段，固定顺序）：行程速览 → 景点 & 餐厅总览 → 行程方案 → 人文背景·讲给孩子听 → 营业时间 & 行程复核 → 酒店推荐 → 天气影响评估 → 实用贴士。

### 硬规则（详见 `../AGENTS.md`）
- 嵌入完整 XBrain Logo（IP 规范不可简化）；首屏 `id="top"`；Logo `href="../index.html"`。
- 营业时间须**联网核实**（§13.1）；人文/历史类补「人文背景·讲给孩子听」（§13.5）。
- 出行前**联网核实天气**并补「天气影响评估」（§13.8）。
- 方案深链：`#方案id` 可直开（§13.9）。
- 发布前校验：`<div>` 数成对；行程表每行 4 列；画廊图片路径真实存在。

## 二、纯游记 / 记录型（site-template-travelogue.html）

1. 复制 `site-template-travelogue.html` → `四季景点/<新子站>/index.html`。
2. 同上述换图、填 `{{...}}`、换肤（`--accent` 默认暖金，可改）。
3. 按章节写：hero（含日期/同行/交通/天气 meta）→ 行程总览（关键事实卡）→ 游记实录（若干 `.log-chapter`，每章时间标签+叙述+可选组图）→ 美食 & 随手发现 → 实用信息。

> 其 `.log-chapter` / `.food-card` 与攻略型同源，均来自公共核心 `site-template-travelogue-core.html`。

### 与攻略型的区别（重要）
- **无**多方案切换、无强制「营业时间 & 行程复核」、无出行前天气预警——它是**事后记录**。
- 营业时间 / 花费 / 停车等写在「实用信息」，属**回忆性备注，非出行前强制联网核实**；如需严谨规划请改用攻略型。
- 结构更轻：核心是 `.log-chapter` 游记章节（复用 `.media-block` 组图组件）。

## 三、游记核心模块（公共单一来源）

`site-template-travelogue-core.html` 是「游记 / 记录」功能的**公共核心**，被两套模板共同引用：

- `site-template.html`：**攻略/规划型**在制定方案后，于「行程方案」section 之后追加本模块（即 `#log` 游记实录 + `#food` 美食发现），用于记录实际执行的行程。
- `site-template-travelogue.html`：**纯游记/记录型**本身就是本模块的载体（轻量：总览 → 实录 → 美食 → 实用信息）。

### 为什么抽出来
制定方案 → 实际出行执行 → 在「实际执行的方案」之后追加「游记」，是同一个「记录」能力的两次复用。把 `.log-chapter` / `.food-card` 的样式与结构抽成单一来源，可避免两份模板各自漂移。

### COPY BLOCK 三段约定（沿用 brand/top-nav-template.html）
该核心文件用三段注释框定可复制内容，目标模板直接复制即可：

| 段 | 内容 | 粘贴到 |
|----|------|--------|
| `COPY BLOCK 1/3` | `.log-chapter` / `.food-card` 家族 CSS | 目标模板 `<style>` 内任意位置 |
| `COPY BLOCK 2/3` | `#log` + `#food` 两个 section 的 HTML 骨架 | 目标模板 `<body>`，「行程方案」section 之后 |
| `COPY BLOCK 3/3` | 入场动画选择器扩展（把 `.log-chapter, .food-card` 并入现有 reveal observer） | 目标模板已有 `<script>` 的 reveal 选择器 |

> 本文件本身可浏览器直接打开，作为游记模块的**独立预览**。主题无关：只依赖两模板 `:root` 均已定义的令牌（`--accent` 等），暖金/冷蓝皮肤下均正确渲染。配图复用两模板共有的 `.media-block`。
